# Как выложить и дать коллегам одну команду

## Один раз для владельца

1. Создайте публичный репозиторий, например `VKarmani-Node`, с основной веткой `main`.
2. Распакуйте архив. Загрузите **содержимое папки**, а не ZIP и не родительскую папку:
   в корне репозитория должны оказаться `install.sh`, `README.md`, `.gitignore`,
   `.gitattributes`, каталоги `build`, `tests`, `tools` и `.github`.
3. Замените `OWNER/REPO` в примере README на GitHub-логин и имя этого репозитория.
   Сам `install.sh` менять не требуется. Дождитесь результата проверки в Actions
   и отдельно проверьте развёртывание на тестовой VPS перед массовым использованием.

Через браузер: **Add file → Upload files → загрузить файлы → Commit changes**.
Через GitHub Desktop: скопируйте содержимое папки в локальный репозиторий, проверьте
список изменений, выполните Commit и Publish/Push. В архиве уже LF-переносы строк;
не пересохраняйте shell-файлы с CRLF. Загрузка через веб не применяет `.gitattributes`.

## Команда коллегам

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/OWNER/REPO/main/install.sh)
```

`OWNER/REPO` здесь намеренно шаблон, не существующая ссылка на опубликованный проект.
Например, если ваш репозиторий — `your-team/VKarmani-Node`, в URL ставится ровно
`your-team/VKarmani-Node`. Команда выполняется от root в Bash на чистой VPS.
Для обычного пользователя сначала `sudo -i`; пароль sudo — это требование ОС, не вопрос установщика.

Автоматически получить команду из адреса репозитория:

```bash
python3 tools/install-command.py https://github.com/OWNER/REPO
```

После успешного GitHub Actions готовая команда с конкретным SHA появляется
в Summary задания. Предпочтительнее распространять проверенный полный commit SHA
вместо изменяемой ветки `main`. Ни один установщик не проверяет надёжность владельца
произвольной ссылки: root-команды запускайте только из проверенного вами репозитория.

Для контроля ошибки HTTP/сети отдельно от Bash можно использовать одну составную команду:

```bash
( f=$(mktemp) && trap 'rm -f "$f"' EXIT && curl -fsSL --proto '=https' --proto-redir '=https' --connect-timeout 15 --max-time 180 https://raw.githubusercontent.com/OWNER/REPO/main/install.sh -o "$f" && test -s "$f" && bash "$f" )
```

Короткий вариант `<(curl ...)` поддержан, но код возврата curl не становится автоматически
кодом возврата Bash: при полностью пустом ответе `bash` может закончиться с кодом 0.
При обрыве внутри тела установщика функция не будет исполнена, поскольку сначала должна
полностью пройти разбор Bash. Это не проверка подписи и не защита от изменённого злонамеренного исходника.

## Не загружать

Не добавляйте прежние пользовательские compose с ключом, папки установленной VPS,
`remnanode.env`, `profile.json`, `reality.json`, сертификаты, резервные копии,
вывод `docker inspect` или журналы без проверки. В архиве нет зашитого IP вашей панели.
`.gitignore` защищает только от обычного добавления неотслеживаемых файлов через Git:
он не удаляет секреты из истории и не блокирует их загрузку через веб или `git add -f`.

Эта поставка подготовлена для загрузки. Создание репозитория и публикация в аккаунте
владельца не выполнялись при сборке архива.
