# Безопасность

Установщик выполняется от root: используйте только просмотренный вами исходник,
чистую выделенную VPS, снимок диска и консоль хостера. Не запускайте в сервере панели.
Новые внешние shell-скрипты во время установки не выполняются: программы берутся
из репозиториев ОС и Docker, контейнер — из официального Remnawave repository.
Первая загрузка `latest` фиксируется digest; это не независимая проверка происхождения
образа и не тест совместимости с конкретной версией вашей панели.

В публичной поставке нет заранее заданного адреса панели, рабочего SECRET_KEY,
API-токена или статического приватного REALITY-ключа. Ввод собирается из `/dev/tty`;
SECRET_KEY скрыт, не экспортируется в окружение установщика и не передаётся аргументом
внешнему процессу. В stdin внутреннего обработчика он присутствует ожидаемым образом.
После установки ключ хранится в `/etc/vkarmani-node/remnanode.env` (0600), а контейнер
получает его через environment, как предусмотрено RemnaNode. Root и пользователи
с доступом к Docker всё равно способны прочитать этот секрет.

Приватные данные также находятся в `reality.json`, `profile.json`, ключах Certbot,
резервных копиях SSH-конфигурации. Не публикуйте их и не выводите полный `docker inspect`.
Проверяйте журналы перед отправкой: отсутствие штатного вывода секретов не исключает
секретные данные в сообщениях внешнего ПО или пользовательских конфигурациях.

`tools/check-publication.py` ищет несколько видов ключей, токенов и закодированных
Remnawave payload. Это ограниченная локальная эвристическая проверка, не полный аудит
и не гарантия отсутствия секретов. Она показывает путь/строку, а не значение секрета.

Если секрет опубликован, замените/отзовите его в соответствующей системе и проверьте,
что старый не принимается. Удаление текущей строки не очищает историю Git.
Не размещайте приватный ключ или рабочий SECRET_KEY в Issue даже для демонстрации ошибки.

Сетевой доступ к TCP/2222 разрешён только с введённого исходящего IPv4 панели.
Не расширяйте правило до всего интернета для обхода ошибки соединения.
Проверьте адрес, настройки внешнего firewall, Node Port и назначение профиля в панели.

`--no-reboot` отключает только завершающую перезагрузку, не еженедельное расписание.
Для остановки еженедельного reboot: `systemctl disable --now vkarmani-weekly-reboot.timer`
и `rm -f /etc/vkarmani-node/weekly-reboot-enabled`. Повторная установка включит его снова.
