# 🛠️ Remnawave Node · 1.3.4

**VLESS + RAW + REALITY · Nginx Selfsteal · IPv4-only**

Одна команда, три значения: **SECRET_KEY → IPv4 панели → домен ноды**. IPv4 самой ноды выбирается по DNS среди адресов VPS.

> ⚠️ Установщик настраивает VPS, но не создаёт объекты в панели. Локальный `PASS` **не означает**, что панель подключилась. Причина ранее наблюдавшегося внешнего TLS-таймаута окончательно не установлена.

## 🩹 Ошибка network-службы после reboot (обновление 1.3.4)

На уже установленной **ноде 1.3.x**, от root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/SUXARIK-GITHUB/Node_Install/main/install.sh) --repair-network
```

Исправляет обработку отсутствующих IPv6-параметров после `ipv6.disable=1`. Перед изменением сохраняет старый журнал и два управляемых файла. Повторно запускает network-службу и диагностику, **без reboot, остановки RemnaNode, смены ключей/образа, изменения firewall, маршрутов или MTU**.

`NETWORK_REPAIR=PASS` относится только к этой ошибке. Код итоговой проверки `2` означает, что Xray/Selfsteal на `443` ещё не подтверждён, даже если исправление network прошло. Таймаут панели этим не объявляется исправленным.

## 🔧 Остальные исправления установки 1.3.x

На **ноде**, в Bash от root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/SUXARIK-GITHUB/Node_Install/main/install.sh) --repair-node
```

Доступ к серверу панели не нужен. Параметры берутся из сохранённой конфигурации, вопросов нет.

Исправление убирает зависимость API от Nginx, оставляет автозапуск контейнера Docker, ограничивает баны Fail2ban SSH-портами и обновляет локальные TLS/Selfsteal-проверки. Исходный IP панели остаётся обязательным ограничением доступа к `2222`.

**Без переустановки ОС, APT, смены образа, ключей, SSH, маршрутов и MTU. Без reboot.** RemnaNode кратковременно остановится. Перед изменениями создаётся резервная копия управляемых файлов; при ошибке скрипт пытается их вернуть. Добавленное узкое разрешение UFW для IP панели при откате сохраняется.

Режим рассчитан на завершённую установку **этого скрипта 1.3.x**. Он не мигрирует чужие установки. Для незавершённой установки используется обычный запуск.

## 🚀 Установить на чистую VPS

Подготовь чистую Ubuntu **22.04/24.04** или Debian **12/13**: systemd, GRUB, amd64/arm64, от 900 MiB RAM и 6 GiB свободного места. Нужны снимок VPS и консоль хостера.

Домен: одна A-запись на один из публичных IPv4 VPS, без AAAA и CDN-проксирования. Внешний firewall хостера должен пропускать SSH, `80/443`, а `2222` — только с IPv4 панели.

В Bash-терминале **ноды**, от root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/SUXARIK-GITHUB/Node_Install/main/install.sh)
```

```text
[1/3] SECRET_KEY ноды (скрытый ввод):
[2/3] Публичный IPv4 основного сервера (панели):
[3/3] Домен ноды:
```

Укажи исходящий IPv4 backend панели — не адрес Cloudflare. Ничего редактировать внутри скрипта не нужно.

### ⚙️ Что настраивается

| Компонент | Настройка |
|---|---|
| ОС | Обновление пакетов текущего выпуска и безопасная очистка |
| IPv6 | Отключение через sysctl и GRUB; проверка после reboot |
| Время | `Europe/Moscow`, Chrony |
| Перезагрузка | Понедельник, **04:00 МСК** |
| Защита | UFW, Fail2ban только для SSH; вход по SSH сохраняется |
| Сеть | BBR и default fq, без принудительной замены очередей интерфейса |
| Нода | Официальный образ RemnaNode с закреплением digest; Docker `restart: always` |
| Selfsteal | Nginx + Let's Encrypt, TLS 1.3, HTTP/1.1 и HTTP/2 |

После успешной **полной установки** сервер автоматически перезагрузится. Отключить этот разовый reboot можно параметром `--no-reboot`. Полную установку не нужно повторять вместо `--repair-node` на уже настроенной 1.3.x.

## 🔗 Профиль и панель

```text
Панель → любой локальный IPv4 ноды:2222 → RemnaNode API
Клиенты → домен ноды:443 → Xray RAW/REALITY → /dev/shm/nginx.sock → Nginx
```

Nginx не занимает публичный `443` и не обслуживает API на `2222`. Шаблон REALITY использует `target: /dev/shm/nginx.sock`, `xver: 1`. XHTTP нет; Vision принудительно не добавляется.

В панели нужны карточка Node с портом `2222`, назначенный Config Profile, Host и доступ группы. Готовый **локальный шаблон** и памятка:

```text
/etc/vkarmani-node/profile.json
/etc/vkarmani-node/PANEL-SETUP.txt
```

`profile.json` содержит приватный REALITY-ключ. **Не публикуй его.** Действующий профиль панели установщик не изменяет.

## 🩺 Проверка

```bash
vkarmani-node-check
```

Отдельно серверная TLS-проверка API:

```bash
vkarmani-node-tls-check --all-local
```

Проверяются CA, точное совпадение сертификата и обычная/порционная передача ClientHello. **Это локальный TLS-тест, не аутентификация панели и не проверка внешнего маршрута.**

```text
/var/log/vkarmani-node-network-repair.log — исправление network
/var/log/vkarmani-node-repair.log    — остальные исправления
/var/log/vkarmani-node-postboot.log  — после reboot
/var/log/vkarmani-node-install.log   — полная установка
```

Исправление 1.3.4 проверено воспроизведением ошибки procps 4.0.4, тестами фильтрации/проверки sysctl и проверками синтаксиса. Полное развёртывание и reboot на VPS в среде разработки не выполнялись.
