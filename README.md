# VKarmani — установщик ноды Remnawave

**Версия 1.2.0. Одна команда → три значения в начале → автоматическая установка сервера.**

Устанавливает RemnaNode, Docker, UFW, Fail2ban, Nginx и Let's Encrypt.
Настраивает локальный Selfsteal для VLESS + XHTTP + REALITY, IPv4-only,
московское время и перезагрузку в понедельник в 04:00 МСК.

> Для **чистой отдельной VPS**, не для сервера панели и не поверх чужой ноды.
> Перед запуском сделайте снимок и проверьте доступ к консоли хостера.
> Скрипт обновляет ОС, изменяет firewall и загрузку ядра, затем перезагружает сервер.

## Установка

В команде ниже **OWNER/REPO — шаблон**. Владелец репозитория заменяет его своим
GitHub-логином и названием репозитория и передаёт коллегам уже готовую команду.
Внутри `install.sh` никаких адресов редактировать не нужно.

Выполните в Bash-терминале сервера **от root**:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/OWNER/REPO/main/install.sh)
```

Не подставляйте ссылку `github.com/.../blob/...`: нужна именно raw-ссылка.
Если вошли обычным sudo-пользователем, сначала выполните `sudo -i`.
При отсутствии curl: `apt-get update && apt-get install -y curl ca-certificates`.
Git, клонирование репозитория, Python и ручной запуск Docker перед установкой не нужны.

После коротких локальных проверок, **до обновления и установки пакетов**, появятся:

```text
[1/3] SECRET_KEY ноды (скрытый ввод):
[2/3] Публичный IPv4 основного сервера (панели):
[3/3] Домен ноды (например, ee1.example.com):
```

Вставляйте ключ одной строкой; ввод не отображается. Допустима строка `SECRET_KEY="..."`.
**IP основного сервера — исходящий IPv4 backend панели**, с которого она соединяется
с нодой, а не IP Cloudflare, адрес компьютера установщика или IPv4 самой ноды.
Домен укажите без `https://`, пути и порта. Дальше установщик вопросов не задаёт.
Ошибочные значения приводят к остановке, а не к опасным догадкам.

Управляющий порт фиксирован: **TCP/2222**. В панели должен быть указан тот же Node Port.
Клиентский порт — **TCP/443**. Email для ACME не требуется; условия Let's Encrypt
принимаются автоматически при запуске установки.

Повторный запуск использует сохранённые значения и ключи, не задаёт вопросы заново.
После успешных локальных проверок сервер перезагружается автоматически.
При ошибке завершающий reboot не назначается; повторите команду после исправления причины.
Не закрывайте SSH-сеанс до завершения: отдельного фонового установщика здесь нет.

## Что подготовить заранее

Поддерживаемый кодом список: Ubuntu 22.04/24.04, Debian 12/13; amd64/arm64;
обычная VPS/VM с systemd и GRUB, не менее 900 MiB RAM и 6 GiB свободного места.
Нужен публичный IPv4, непосредственно назначенный интерфейсу сервера.
NAT, IPv6-only, LXC/OpenVZ и systemd-boot этим установщиком не обслуживаются.
Проверки кода не означают испытание развёртывания на всех перечисленных ОС.

Домен должен иметь **одну A-запись на IPv4 ноды, без AAAA и CDN-проксирования**.
В сетевом firewall хостера нужны входящие TCP/80, TCP/443 и ваш SSH-порт;
TCP/2222 — только с IPv4 панели. Скрипт управляет UFW на VPS, но не кабинетом хостера
и не DNS-провайдером. Для HTTP-01 выпуск/продление сертификата требует внешнего доступа к TCP/80.

## Важная граница: сервер и панель

**На VPS всё устанавливается автоматически. Но SECRET_KEY не даёт прав управления панелью.**
Скрипт не создаёт и не изменяет Node, Config Profile, Host или Internal Squad.
Панель должна иметь карточку ноды с её IPv4, портом 2222 и назначенным совместимым профилем.
Тогда она сможет обратиться к ноде и передать конфигурацию после запуска сервисов.

Для новой настройки установщик создаёт готовый JSON и персональную памятку:

```bash
cat /etc/vkarmani-node/PANEL-SETUP.txt
cat /etc/vkarmani-node/profile.json
```

Импортируйте JSON в Config Profiles, назначьте профиль/inbound ноде, создайте Host
и разрешите inbound нужному Internal Squad. JSON содержит приватный REALITY-ключ:
**передавайте только в свою панель, не публикуйте**.
Если профиль уже есть, скрипт его не заменяет.

Selfsteal здесь — свой Nginx на **127.0.0.1:8444**, действующий сертификат,
локальная страница и REALITY `target: 127.0.0.1:8444`, `xver: 0`.
В JSON-шаблоне SNI равен введённому домену, транспорт — XHTTP, без Vision flow.
Отдельная программа `selfsteal` DigneZzZ не устанавливается; старый профиль
с `/dev/shm/nginx.sock` / `xver: 1` не совместим без изменения target.

## Что выполняется автоматически

| Область | Настройка |
|---|---|
| Обновления | APT full-upgrade текущего выпуска; без перехода на другую версию дистрибутива. Имеющиеся snap обновляются, если snapd работает. |
| Очистка | APT-кэш, ненужные пакеты, ограниченные старые журналы, старые dangling Docker-образы. Без удаления volumes и контейнеров. |
| IPv6 | Runtime sysctl + `ipv6.disable=1` в GRUB; проверка полного отключения после reboot. |
| Время | Europe/Moscow, Chrony. |
| Ребут | Каждый понедельник 04:00 МСК, без «догоняющего» reboot при пропуске расписания. |
| Сеть | BBR + fq; UFW с доступом к 2222 только с введённого IPv4 панели. |
| SSH | Сохраняются существующие порты и аутентификация; Fail2ban; без принудительного парольного входа root. |
| Docker | Официальный репозиторий; образ RemnaNode фиксируется digest, host networking, автозапуск. |
| TLS | Nginx + Certbot webroot, тест продления, timer и reload hook. |
| После загрузки | Автозапуск служб и локальная диагностика. |

## Проверка после reboot

```bash
vkarmani-node-check
```

`NODE_SETUP=PASS` означает, что проверен сервер, **не сквозное VPN-подключение**.
До получения профиля нормально увидеть `VPN_STATUS=WAITING_FOR_PANEL_PROFILE`.
`PANEL_CONNECTION=NOT_VERIFIED` честно отражает отсутствие API-проверки панели.
Даже обнаруженные Xray/cover не заменяют проверку подписки обычным клиентом.

Дополнительно:

```bash
vkarmani-node-check --require-xray
systemctl list-timers --all vkarmani-weekly-reboot.timer
tail -n 100 /var/log/vkarmani-node-postboot.log
```

В конце исходной команды можно добавить `--no-reboot` (только финальный reboot)
или `--refresh-image` (явно обновить закреплённый образ существующей установки).
Обычный reboot сам по себе не обновляет Docker-образ.

## Публикация и разработка

Для публикации: [PUBLISH-RU.md](PUBLISH-RU.md). Секреты: [SECURITY.md](SECURITY.md).
Проверки и ограничения: [TEST-REPORT.md](TEST-REPORT.md).
Исходники и тесты уже внутри репозитория; на VPS нужен только **install.sh**.

GitHub Actions проверяет код без установки ноды и выводит в Summary команду
с реальным именем репозитория и фиксированным проверенным commit SHA.
Проверка в Actions запускается после загрузки файлов; локальная подготовка архива не является её результатом.

```bash
python3 build/rebuild.py
python3 -m unittest discover -s tests -v
python3 tests/check_artifacts.py
python3 tools/check-publication.py
```

На машине разработчика для тестов нужны Python 3.10+, cryptography, pexpect,
Bash, curl, systemd-analyze, OpenSSL и Nginx. Сам установщик необходимые зависимости ставит сам.
**На действующей VPS эта версия в рамках подготовки архива не развёртывалась.**
