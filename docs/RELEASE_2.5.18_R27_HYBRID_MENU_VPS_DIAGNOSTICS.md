# Node Install 2.5.18 r27 — гибридное меню, мастер установки, диагностика VPS

**Дата:** 2026-11-05. **Статус:** `INCOMPLETE_STAGING_ONLY` (не production и не готовая деинсталляция). Основа — полный r26 ZIP; никакие данные действующих нод, Remnawave, GitHub или VPS не изменялись в ходе подготовки архива.

## Общее устройство

- `bash install.sh` в интерактивном терминале теперь открывает полноэкранное меню curses стандартной библиотеки Python. Для явного вызова: `sudo bash install.sh --menu`; для исходного установщика без меню: `sudo bash install.sh --install-direct`.
- Совместимые прежние CLI-вызовы (`--site-manager`, `--finalmask`, `--diagnose-network`, `--transport-readiness`, `--backup`, `--rollback-image`, `--check` и другие) сохранены. Диагностические команды не вызывают обычную установку.
- Цвета: чёрный фон, зелёный текст, подсветка выбранного пункта; отдельно обозначаются предупреждения и ошибки. Стрелки/j/k, Enter, Esc, цифровой выбор, PgUp/PgDn/End для журнала. Не используются внешние TUI-библиотеки, не запускаются дополнительные службы, демоны или базы данных.
- В терминалах без поддержки curses предусмотрен **ограниченный** текстовый интерфейс (диагностика и план удаления), **НЕ** аварийный упрощённый установщик. Установка из такого окружения не запускается автоматически.
- Отдельный экран журнала запускает проверенную штатную команду, читает её stdout/stderr, ограничивает отображаемый объём и не сохраняет консольный вывод в новые файлы. Долгий процесс установки не прерывается произвольным Esc — это не является безопасным rollback.

## Главный экран

1. **Проверка VPS**: быстрый локальный обзор, HTTPS сервисов, ICMP, HTTPS p50/p95/jitter и пики, traceroute, отдельный TCP iperf3 тест скорости, Cloudflare colo/loc, собственный публичный домен, ядро, опциональная приватная история результатов.
2. **Установка Node**: Ordinary, Cascade Entry, Cascade Exit. Роль выбирается первой. Для Ordinary **первым пунктом сайта** является `00. АВТО (РАНДОМ)`, затем поиск, категории и перечень 120 реальных сайтов. Автовыбор один раз за запуск мастера, без ежедневной ротации и без изменения темы после подтверждения.
3. **Отменить неудачную установку**: показывает фактические маркеры/ограничения и предлагает только существующий, строго ограниченный аварийный откат SSH/UFW при подтверждённой незавершённой установке с вооружённым marker. Нет универсального повторного запуска или очистки состояния.
4. **Полное удаление Node Install**: только инвентаризация, предупреждение и предложение восстановить **проверенный снимок VPS до установки** через панель провайдера. Автоматическая полная деинсталляция НЕ реализована, потому что установщик изменяет APT/GRUB/SSH/UFW/Docker/сертификаты/IPv6 всей ОС и локальные backup не способны доказать безопасное полное восстановление. Проект не стирает журналы аудита ради сокрытия следов. `full-removal` возвращает `STOP` без изменений.
5. **Управление Node**: диагностика, список/смена сайтов на staging, Nginx/Selfsteal, FinalMask только для клиентского JSON, RKN Guard, версии, обслуживание, backup, справка о подготовленных дополнительных транспортах.

## Шаги мастера установки

1. Выбор роли Ordinary / Entry / Exit.
2. Для Ordinary выбор сайта; `00` = криптографически случайная тема из 120, фиксируемая до установки. Список содержит ID и тему; поиск и категории работают локально. Cascade Entry/Exit не получают опциональный cover.
3. Для Cascade — проверка приватного абсолютного пути к role-bundle. Для любой роли — скрытый ввод SECRET_KEY, затем FQDN и публичного IPv4 панели. Валидируются значения до изменения ОС.
4. Для Ordinary — REALITY/SNI из пяти уже поддерживаемых вариантов и RAW+REALITY+Vision. Экспериментальные XHTTP/TLS/H2, Hysteria2 и AWG2 **не считаются установленными транспортами** и не активируются автоматически.
5. **Дополнительные параметры необязательны:** отдельный первый пункт «Пропустить». При выборе можно задать Ordinary Node API порт и обслуживание, разрешить reboot. Базовый мастер по умолчанию **отключает автоматическую перезагрузку** для проверки доступности консоли.
6. Обзор публичных параметров и рисков (SECRET_KEY не выводится), явный ввод `INSTALL`, только затем запуск штатного `install.sh`. Его собственные проверки ОС, свободных портов, ownership, контрольных сумм архива, snapshot/SSH/UFW, конфигураций и checkpoint остаются обязательными; меню их не отменяет.
7. Журнал с постраничной прокруткой и итоговый код (`0` полный локальный успех; `20` базовая нода установлена, но выбранный сайт не опубликован). Успех не доказывает соединения реальных клиентов.

### Защита секретов в мастере

SECRET_KEY не передаётся в аргументах процесса (`ps`) или в переменных окружения. На Linux он передаётся штатному установщику через временный **анонимный memfd**, fd наследуется только конкретным дочерним процессом и проверяется по `/proc/self/fd`. Используется встроенная проверка корректности FQDN/IPv4/ключа. Внешние диагностические команды никогда не получают ключ. В новых отчётах нет содержимого клиентских соединений, приватных ключей или cookie. Если нет безопасного memfd/TTY — мастер останавливается.

## Диагностика VPS

| Запуск | Реальный смысл | Чего он НЕ доказывает |
|---|---|---|
| `bash install.sh --vps-check local` | ОС, RAM, диск, маршрут, состояния служб/портов, маркеры установки | Реальную установочную пригодность без preflight установщика |
| `bash install.sh --vps-check services` | HEAD HTTPS к VK, Yandex, MAX, YouTube, Reddit, GitHub, X, ChatGPT, DeepSeek, Grok, Claude и API | Доступность аккаунта, видео, подписки или отсутствие геоблокировки |
| `bash install.sh --vps-check ping --host github.com` | Ограниченная ICMP-проверка, loss %, min/avg/max и mdev | Что узел обязан отвечать на ICMP, или доступность по HTTPS |
| `bash install.sh --vps-check quality --host github.com` | Повторяемый HTTPS TTFB, p50/p95, jitter, скачки, процент ошибок | Пинг ICMP, скорость VPN, эффективность обхода DPI |
| `bash install.sh --vps-check trace --host github.com` | До 15 видимых узлов через системный traceroute, если он уже есть | Полный маршрут или потерю трафика в узле с `*` |
| `bash install.sh --vps-check speed --server 1.2.3.4` | Ограниченный TCP upload + reverse download до **своего** iperf3 сервера | Speedtest обычного клиента или пропускную способность через VPN |
| `bash install.sh --vps-check edge` | Cloudflare colo/loc по HTTPS c раскрытием VPS IP поставщику | Точное расположение пользователя или всех CDN |
| `bash install.sh --vps-check custom --host your.example.com --port 443` | Одно HTTPS-соединение без следования редиректам | Доступ к личному кабинету и корректность всего приложения |

Для человекочитаемых таблиц добавьте **перед действием** `--format table`, например `bash install.sh --vps-check --format table services`. По умолчанию вывод JSON, пригодный для автоматизации. Сервисный `401` означает потребность в авторизации, `403/451` — не доказательство геоблокировки, `429` — rate limit, сетевые ошибки отделены от HTTP-ответов.

Все внешние вызовы явные, без запуска установочного мастера и без установки пакетов. Цели HTTPS проверяются на публичный IPv4 после DNS-разрешения; приватные, loopback и mixed/private DNS ответы блокируются (предотвращение SSRF). Тайм-ауты, размер ответов и число проб ограничены. Не выполняются запросы с пользовательскими cookie/ключами; нет загрузки или исполнения удалённого кода. CDN-запрос раскрывает Cloudflare публичный адрес VPS (об этом предупреждает меню).

### Опциональная история

По умолчанию **не сохраняется**. Переключатель в меню «Сохранение результатов» и CLI `--save` явно разрешают сохранение локального агрегированного JSON в `~/.local/state/vkarmani-network-diagnostics` с владельцем текущего пользователя и правами `0700`, файлы `0600`, не более 100 отчётов. Вновь сохранённые отчёты содержат имя проверенного домена и агрегаты (а не токены). `history`, `show`, `compare` доступны отдельно. Команды удаления истории не создаются.

## Известные ограничения / критичные условия

- **Полная автоматическая очистка VPS отсутствует** намеренно. Системная конфигурация и пакеты после установки не имеют универсального обратного преобразования. Не удаляйте `/var/lib/vkarmani-node/` вручную, если установка не завершена. Сначала точная диагностика, проверенный snapshot, провайдерская консоль.
- Не выполнена установка на настоящей VPS, перезагрузка, живое TLS/Client/Panel испытание, тест пропускной способности и выбор оптимальных режимов для конкретной сети. Проверены только код и изолированные offline-сценарии.
- `FinalMask` остаётся опцией **экспорта клиентского Xray JSON** с ручными числами; не устанавливает серверный inbound и не меняет подписки Panel.
- UI-диагностика доступна в обычном SSH-терминале; если нет `ping`/`traceroute`/`iperf3`, команда честно сообщает `TOOL_NOT_INSTALLED`, никаких пакетов автоматически не устанавливает.
- Действующие команды проверки и восстановления не запускают перезапись существующих нод. При изменении статуса устанавливать заново нельзя; нужны действующие процедуры восстановления или snapshot.

## Проверка релиза

```bash
cd Node_Install
bash -n install.sh
python3 scripts/verify_release.py --root .
sha256sum --check SHA256SUMS
python3 -m unittest tests.test_r27_terminal_ui tests.test_r27_vps_connectivity tests.test_r27_removal_plan
bash tests/run.sh
bash install.sh --menu --preview-main
bash install.sh --vps-check --format table local
```

**Rollback** нового интерфейса: после отката проверенного snapshot VPS использовать предыдущий полный r26 ZIP; на работающей ноде не заменять `install.sh` вслепую. Новая UI-оболочка не мигрирует ни конфигурации, ни БД, ни Docker volumes. Чтобы использовать исходный прямой мастер из r27, предусмотрен `--install-direct`.
