# Selfsteal / iptables / HAProxy / Nginx — разбор источников 2.2.0

Исследование выполнено для локального выпуска 2026-10-02. Для свежего пользовательского опыта принят согласованный срез 2026-09-17…2026-10-01. Текущие страницы main и официальная документация прочитаны на дату исследования: без snapshot нельзя утверждать, что эти exact bytes были в main 1 октября. Старый закреплённый исходный код применяется для объяснения именно установленного core, а не выдаётся за свежий сетевой эксперимент.

## Источники и применимость

1. [eGames README](https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/main/README.md): прочитаны назначение и disclaimer. Сам автор не позиционирует проект как готовую production-гарантию. Из этого не следует, что все реализации Selfsteal одинаковы.
2. [eGames install_node.sh](https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/main/src/nginx/install_node.sh): прочитан целиком (177 строк на снимке). Собственная TLS-страница через PROXY/Unix socket и default TLS rejection полезны как архитектурный ориентир. В данной реализации Nginx контейнерный, используется общий /dev/shm, NET_ADMIN, latest node и удаление stale socket. Это не перенесено в нашу dedicated host-Nginx/read-only-socket/UFW схему.
3. [eGames selfsteal_templates.sh](https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/main/src/modules/selfsteal_templates.sh): прочитан целиком (510 строк на снимке). Есть случайный выбор/несколько источников шаблонов и клонирование сайта. URL ZIP содержит commits, но путь через сторонние download mirrors проверяет формат PK, не trusted artifact hash; публикация и cleanup не равны нашему atomic index + receipt rollback. Мы реализовали свои четыре builtin страницы без внешнего скачивания/JS/копирования брендов.
4. [MIT LICENSE eGames](https://raw.githubusercontent.com/eGamesAPI/remnawave-reverse-proxy/main/LICENSE): изучена лицензия. В выпуск не переносились значительные фрагменты исходников, чужие HTML/assets или сборки; атрибуция идеи сохранена здесь. Если в будущем копировать substantial code, нужно сохранять copyright/permission notice по лицензии, не удалять авторство как маскировку.
5. [Issue #169](https://github.com/eGamesAPI/remnawave-reverse-proxy/issues/169), открыто 2026-09-22: оператор Ubuntu24.04 сообщает, что HAPP/INCY показывает ping, но доступа в Интернет нет. Логи не приложены, root cause не установлен. Это допустимое свежее наблюдение о границах диагностики, не доказательство дефекта Nginx/REALITY и не сравнение скорости двух архитектур.
6. [Xray26.7.28 go.mod](https://raw.githubusercontent.com/XTLS/Xray-core/v26.7.28/go.mod): закрепляет REALITY `v0.0.0-20260322125925-9234c772ba8f`.
7. [Закреплённый REALITY tls.go](https://raw.githubusercontent.com/XTLS/REALITY/9234c772ba8f/tls.go): `Server` соединяется с target до завершения аутентификации, отправляет PROXY1/2 при xver и использует target при handshake. Ошибка DialContext закрывает клиентское соединение. Вывод: target важен для доступности новых подключений; весь VPN-payload не превращается в обычный HTTP reverse-proxy. Это семантика исходников, не новый packet-capture нашего deployed бинарника.
8. [REALITY README](https://raw.githubusercontent.com/XTLS/REALITY/main/README.en.md): требования/ограничения target и предупреждения о шаблонах fallback. Не все советы можно переносить на новые пакеты; например OCSP ниже.
9. [Nginx SSL module](https://nginx.org/en/docs/http/ngx_http_ssl_module.html): `ssl_reject_handshake` введён в1.19.4. Поэтому введён feature gate, а не ломающее Ubuntu22 требование нового пакета.
10. [Nginx headers module](https://nginx.org/en/docs/http/ngx_http_headers_module.html): старое наследование `add_header` отключается при наличии хотя бы одного child add_header; новая `add_header_inherit` только1.29.3. В наших location нет child add_header; cache настроен через expires, сохраняются CSP/защитные headers, проверены304/404.
11. [Nginx core](https://nginx.org/en/docs/http/ngx_http_core_module.html): `disable_symlinks`, timeout и ranges. `send_timeout` измеряет паузу между операциями, не lifetime всего соединения. Список публикуемых путей выбран нами под закрытый статический генератор, это не универсальный vhost для любой CMS.
12. [Nginx stream ssl_preread](https://nginx.org/en/docs/stream/ngx_stream_ssl_preread_module.html): извлекает SNI/ALPN без TLS termination; это L4-направление, не HTTP L7. Модуль/новая топология нам не нужны для одного существующего RAW listener.
13. [HAProxy3.0 configuration](https://www.haproxy.org/download/3.0/doc/configuration.txt): рассмотрен раздел mode TCP/HTTP. TCP-прокси уместен для реальной задачи распределения нескольких backend, но добавляет конфигурацию/сокеты/точку отказа; режим HTTP не является прозрачным прямым RAW/REALITY. Производительность HAProxy относительно текущего direct-пути не измерялась; не объявляем его всегда медленнее.
14. [iptables extensions](https://man7.org/linux/man-pages/man8/iptables-extensions.8.html): packet/string matching не является полноценным TLS/TCP stream-parser; фрагменты и segmentation нельзя надёжно интерпретировать как целый ClientHello. Не добавлять brittle SNI string drop и дублирующие UFW правила.
15. [Docker host driver](https://docs.docker.com/engine/network/drivers/host/): host namespace без отдельного published-port mapping. Наши RemnaNode используют этот режим; новые DNAT/DOCKER-USER цепочки не вводились как универсальная защита.
16. [Let's Encrypt OCSP retirement](https://letsencrypt.org/2025/08/06/ocsp-service-has-reached-end-of-life/): официальное завершение OCSP в2025, переход кCRL. Старый совет безусловно включать ssl_stapling для LE не переносится. Это исторический первичный источник о механизме, не свежий отзыв пользователя.

## Что исследование НЕ доказало

Не найден надёжный свежий сравнительный опыт Reddit/форумов за выбранные две недели, который устанавливал бы прирост скорости, срок до IP-бана или превосходство HAProxy/iptables над нашим direct Selfsteal при одинаковых условиях. Поиск включал Reddit и профильные обсуждения; нерелевантные/старые результаты не выдаются за свежие. Нет claims, что прочитан весь Интернет, все issues/repositories или выполнен полный benchmark.

Прочитаны перечисленные выбранные модули eGames и доступный issue. Полную runtime-установку/clone всего проекта eGames получить/выполнить в этой среде не удалось; он не запускался. Технические решения основаны на указанных исходниках и своих тестах, а не на недоступных комментариях.

## Принятые проектные решения (наша инженерная оценка)

Сохранить Xray443 → ownUnixNginx, без HAProxy, новых IP-ban-листов, HTTP-проксирования VPN или XHTTP. Улучшать предсказуемость target и статическую поверхность: negativeSNI/Host, exactroutes, MIME/security/cache, ограничения чтения/atomicstate и стабильные темы. Нейтральная мини-страница остаётся узнаваемым шаблоном для знающего наблюдателя; случайность не равна недетектируемости. Публичное DNS/сертификат/CT не скрываются.

Ключевые риски для отдельных пилотных проверок: несовместимые старые Nginx, ошибочный SNI/Host override клиента, HTTPvhost реальной панели, bootstrap/renewal/reboot, права socket после загрузки, пропуск malformedTLS/большогоClientHello, внешняя сеть и kernel steal. Локальные реальные Nginx-тесты закрывают только часть, остальное требует VPS и пользовательского клиента.
