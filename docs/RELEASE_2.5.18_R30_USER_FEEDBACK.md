# Node Install 2.5.18 r30 — этап 1/2: пять пользовательских исправлений

**Статус: INCOMPLETE_STAGING_ONLY.** Это полные исходники для проверки на **новой тестовой VPS** с рабочей консолью провайдера и проверенным snapshot. Не мигрирует существующую установленную Node, изменения в действующую VPS не отправлялись. Проверка реального трафика, MobaXterm и SSH/TLS в staging нужна отдельно.

## Ровно пять пунктов в этом обновлении

1. **Esc/возврат:** мастер работает как последовательность шагов. Esc возвращает к предыдущему шагу, а не в главное меню (кроме первого шага); введённые обычные значения сохраняются до запуска. Ошибки валидации оставляют на текущем шаге. Секрет не передаётся через CLI/ENV, только через анонимный memfd.
2. **Дополнительные настройки:** отдельные пункты для порта Node API, входящей/исходящей скорости, входящего/исходящего накопленного объёма и двух опций перезагрузки. `0` в меню снимает ограничение; значения 1–20 000 Мбит/с, 1–100 000 GiB. Все лимиты выключены по умолчанию. В каскадной роли эти ограничения пока не устанавливаются автоматически (запрещён недокументированный режим).
3. **Подтверждения:** установка и штатное управление без требования вводить `INSTALL`, `FINISH`, `BACKUP` и т.п. Просмотр настроек завершается Enter. Для **отката или операции удаления/сброса квоты** два выбираемых пункта: «Я осознаю что делаю и согласен» и «Я ошибся хочу вернуться назад». Автоматические проверки состояния, файлов, root, SSH и backup **сохранены**.
4. **Панель по IP или домену:** ввод публичного IPv4 или FQDN без `https://` и порта. При домене локальный установщик получает 1–16 публичных A-записей и ограничивает UFW Node API только этими IPv4 (однократно при установке). Не принимает внутренние/резервные адреса. Проксированные CDN-имена могут отличаться от исходящего IP Panel; при DNS-изменении нужен пересмотр ACL.
5. **Цветной, переносимый журнал:** ошибки красным, предупреждения жёлтым, успешные этапы светло-зелёным, APT отдельным цветом; строки переносятся по ширине и листаются PageUp/PageDown/End. ANSI-секвенции и стандартные поля ключей скрываются в отображении; длинные строки ограничены, чтобы не разрушать рамку. Установщик не пишет REALITY private key в tty вне curses (покажет путь к приватному `/root/reality-keys.txt`).

## Сетевые лимиты — эксплуатационные ограничения

Опциональный `integrations/traffic_limits.py` применяет **nftables policing (drop превышающих пакетов)** в собственной `inet vkarmani_node_traffic` таблице, не меняет UFW и чужие nft/tc правила. Обрабатываются IPv4/IPv6 входящие/исходящие пакеты host INPUT/OUTPUT на **одном основном IPv4-интерфейсе**. TCP-порты SSH и Node API исключены для предотвращения блокировки административного доступа. Это не гарантированное «плавное» ограничение через qdisc; сетевой сервис может получить packet loss.

Накопленные объёмы для каждого направления считаются в GiB через отдельные quota/counter объекты, снимки сохраняются каждые 60 секунд (root:0600), после перезагрузки восстанавливаются. Период **сбрасывается вручную** через меню с явным подтверждением, не соответствует автоматически биллинговому периоду хостера. Потери последней минуты при crash/power-off возможны. FORWARD, дополнительные NIC, трафик вне host network и различия учёта у хостера не учитываются, поэтому биллинговую точность обещать нельзя. При исчерпании лимита пользовательский трафик может перестать работать, SSH/Node API исключены; обязателен staging-тест и внешняя консоль.

При ошибке необязательного nft-применения нода может уже иметь `INSTALL_COMPLETE`, но возвращается `INSTALL_RESULT=PARTIAL`, код `21`, без auto reboot. Ошибка сайта — старый код `20`, не решена этим этапом. Возобновление лимитов вручную доступно через «Управление → Сетевые лимиты»; не устанавливать повторно поверх действующей ноды.

## Что осознанно НЕ включено в этап 1

Пункты **6–9** из сообщения пользователя: комплексная переделка внешнего вида интерфейса; отдельная постоянная запись живого журнала в `/root`; выбор/копирование значений `/root/reality-keys.txt` внутри интерфейса; отдельная кнопка «Выйти из установщика». Работу UI с правым нижним краем частично защитили из-за требований пункта 5, но **согласованный референс по шрифтам/отступам не достигнут**. Существующий `0 / Esc` выход из главного меню сохранён.

`SITE_THEME=STOP / VKARMANI_SELFSTEAL_CHECK` (пользовательский `EXIT_CODE=20`) остаётся отдельной проблемой публикации сайта и не считается исправленной в этих пяти пунктах.

## Безопасная проверка

Архив: `Node_Install_2.5.18-docs-menu_20261106-r30-five-fixes-staging.zip`. Распаковать **в новую отдельную папку**, не поверх работающей установки, и перед запуском на VPS:

```bash
cd Node_Install
sha256sum -c SHA256SUMS
python3 scripts/verify_release.py --root .
bash -n install.sh
bash ./install.sh --version
python3 scripts/terminal_ui.py --preview-main
```

Реальную установку и включение сетевых лимитов проводить **только на новой staging VPS**, после проверенного snapshot и проверки SSH-консоли хостера. После установки проверить `sudo vkarmani-node-check`, `nginx -t`, `systemctl status vkarmani-node`, `sudo bash install.sh --traffic-limits status` (если лимиты включены), `systemctl status vkarmani-traffic-limits`, `sudo nft list table inet vkarmani_node_traffic`. Для лимитов провести измерение трафика по входящему/исходящему направлениям и убедиться, что SSH не прерывается. При инциденте сохранять журналы и выполнять откат только через заранее проверенный snapshot VPS, а не удалять nft/UFW вслепую.
