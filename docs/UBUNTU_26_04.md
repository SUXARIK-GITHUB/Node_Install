# Ubuntu 26.04: что адаптировано и что ещё требует приёмки

Выпуск: **2.1.0**, исследование: **30 сентября 2026**.

## Статус без подмены понятий

Ubuntu 26.04 / `resolute` добавлена в проверяемую матрицу установщика. Это **реализованная адаптация, но не подтверждённая полная установка на VPS 26.04**. Локальные тесты выполнены на Debian 13 / Python 3.13 / Nginx 1.26.3. Запустить отдельную Ubuntu 26.04, Docker daemon, systemd/GRUB и её Python 3.14 здесь не удалось: нет доступной VM/Docker-среды; скачивание rootfs из рабочей среды не удалось. Подготовленный CI для userspace 26.04 удалённо не запускался.

Пользователь подтвердил работу панели и VPN у прежней версии **2.0.3 на Ubuntu 24.04**. Это важное эксплуатационное свидетельство, но не тест новой 2.1.0 и не доказательство совместимости с 26.04.

## Существенные отличия и решения

| Область | Реализация 2.1.0 | Граница |
|---|---|---|
| ОС и репозитории | Точное соответствие `ubuntu / 26.04 / resolute`; amd64 или arm64 | Никакой подстановки `noble` при отсутствии пакетов |
| Docker | Официальный подписанный репозиторий нужной ОС; общий APT-план компонентов и Docker до настройки SSH/UFW/GRUB | Временный сбой репозитория остаётся основанием остановиться; подписи не обходятся |
| Chrony / NTS | Сохраняются основной конфиг, `sources.d`, `conf.d`, bootstrap trust и NTS; добавляются `-4`, `port 0`, `cmdport 0` | При неизвестных launch flags/изменённом managed block — STOP; источники не заменяются автоматически |
| Базовые утилиты | Проверка фактических `cp --parents`, symlink, SHA256, `sort -z`, `xargs -0`, `stat`, `timeout`, `date -Is` в временной папке | Не меняются essential packages и реализация coreutils |
| Nginx | Проверяются SSL/HTTP2 build flags; до 1.25.1 — старый синтаксис, после — `http2 on` | TLS curves / REALITY / порт 443 не переделываются |
| Cgroups | На 26.04 требуется cgroup v2 | Установщик не переоборудует cgroup/boot самостоятельно |
| Ресурсы | На 26.04 проверка >=1536 MiB MemTotal, >=6 GiB свободного диска | Это порог допуска, не обещание ёмкости; для пилота разумно 2 GiB RAM или больше |
| SSH | Существующая проверяемая политика парольного входа сохранена | Новую внешнюю SSH-сессию всё равно проверяет оператор; пакетный upgrade может повлиять на службу |

Существующий `systemd-timesyncd` не заменяется Chrony даже на 26.04. Выбирается фактический поддерживаемый NTP-клиент образа хостера. Для нового Chrony добавлена осторожная обработка, но синхронизация по сети на 26.04 в этой работе не выполнялась.

## NTS и исходящие подключения

Штатный NTS использует **TCP/4460** для обмена ключами и **UDP/123** для времени. Это **исходящие** соединения, а не новые публичные порты ноды. UFW сохраняет default allow outgoing. Внешняя политика хостера должна разрешать необходимые исходящие соединения. Если они запрещены, нужно разбирать эту политику, а не отключать проверку времени, TLS или NTS вслепую.

`NTP_SYNC=PASS` подтверждает принятую проверкой синхронизацию. Он **не равен** доказательству, что каждый time source использует NTS: например, DHCP может добавить отдельный NTP-источник. Для ручной приёмки NTS на тестовой 26.04:

```bash
sudo chronyc -n tracking
sudo chronyc -n sources
sudo chronyc -n authdata
```

Не публикуйте неотредактированные внутренние адреса источников времени, если они чувствительны для вашей инфраструктуры.

## Приёмка перед массовой раскаткой

Отдельная чистая VPS 26.04 с назначенным публичным IPv4, systemd + GRUB, консолью и snapshot. Домен — DNS only, одна A, без AAAA. Используйте отдельный домен/профиль, не меняя действующую ноду 24.04.

1. Проверить checksum, установить с теми же тремя значениями. Проверить новую парольную SSH-сессию, не закрывая старую.
2. Назначить профиль/Host в своей панели. Дождаться связи панели и проверить настоящим VLESS RAW REALITY-клиентом.
3. Убедиться в завершении пакетных операций. В согласованное окно выполнить reboot, затем обычный `vkarmani-node-check` и `--require-xray`.
4. Проверить продление сертификата в staging (`certbot renew --dry-run`), API только с IP панели, самовосстановление служб и повторный вход. Не запускать циклы выпуска сертификатов на production CA.
5. Снять срез idle/load, проверить длительное соединение и переподключение клиента; отдельно провести контролируемое обновление/откат образа на пилоте, сохранив исходный digest и snapshot.

Не выполняйте `do-release-upgrade` на работающей ноде ради установки этого выпуска. Обновление ОС — отдельная задача с отдельной приёмкой и rollback.

## Первичные источники

- [Canonical: 26.04 release notes](https://documentation.ubuntu.com/release-notes/26.04/).
- [Изменения относительно 24.04](https://documentation.ubuntu.com/release-notes/26.04/summary-for-lts-users/): Python 3.14, systemd, OpenSSH, rust-coreutils, Chrony.
- [Docker: Ubuntu](https://docs.docker.com/engine/install/ubuntu/): Resolute 26.04 включена в список поддерживаемых ОС, репозиторий соответствует codename.
- [Ubuntu: Chrony](https://ubuntu.com/server/docs/how-to/networking/chrony-client/): NTS pools, bootstrap trust, исходящие порты и диагностика authdata.
- [Nginx HTTP/2](https://nginx.org/en/docs/http/ngx_http_v2_module.html): `http2` directive с 1.25.1.

Документы описывают компоненты. Из них не следует автоматическая совместимость всего нашего установщика с каждым образом VPS.
