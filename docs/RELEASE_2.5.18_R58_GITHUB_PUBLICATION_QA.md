## Отчётность и rollback

Полный набор офлайн-тестов запускается **после упаковки** из чистой распаковки; его фактические результаты прикладываются отдельным отчётом, а не заранее объявляются в исходниках. Негативные тесты не запускают `install.sh --menu` без заглушки. Подлинность origin-репозитория и подписей коммитов не подтверждается локальными SHA из самого Git, нужна доверенная контрольная сумма ZIP или отдельная подпись.

Перед загрузкой в Git сохраните доступную предыдущую сборку r58 в архиве или отдельной Git-ветке/теге. Не делайте `push --force`, не удаляйте runtime-данные, не применяйте staging на рабочем сервере без проверенных резервных копий и канала экстренного доступа. Для VPS-отката требуется независимый snapshot, а не только старый ZIP.

## Дополнение: совместимость с Debian 12 / coreutils 9.1 (2026-11-13)

После публикации GitHub Actions `debian-userspace (debian:12)` выявил два падения `tests/test_r54_verified_backup.py`. Причина — несовместимость GNU `cp -a --parents` с абсолютными исходными путями в coreutils 9.1 (Debian bug #1054128). Первоначальный тест повторял ту же ошибочную форму.

Исправлен **фактический backup-блок** `install.sh`: для каждого пути выполняется копирование из `/` с относительным именем и `cp -a --parents`, без изменения списка каталогов, разрешений, места хранения, контрольного SHA256, маркеров установки или восстановления. Никаких новых зависимостей. Регрессия теперь повторяет эту же команду в изолированном fixture-каталоге, проверяет две сохранённые записи и сценарии с отказом/повтором.

**Требуется:** повторный запуск GitHub Actions на Debian 12/13 и Ubuntu после публикации новой сборки. Локальная регрессия на новой системе сама по себе не является доказательством успешной CI на Debian 12. На рабочие VPS ничего не применялось.
