# Node Install r36 — восстановление SSH-экрана после сворачивания

## Симптом

На PuTTY/MobaXterm после сворачивания или простоя окно иногда становится чёрным либо показывает части рамок. При этом дочерний процесс установки продолжает выполняться, а интерфейс `curses` не отправляет данные, если пользователь не меняет выбор или установка долго не пишет новый вывод.

## Причина и исправление

В r35 статические экраны ожидали `getch()`/`get_wch()` без тайм-аута. В журнале перерисовка происходила только при новых данных/клавишах. Когда визуальный буфер удалённого терминала терялся, внутренний виртуальный экран `curses` оставался прежним; обычный инкрементальный `doupdate()` не мог восстановить физическую картину.

В r36:

- `SCREEN_POLL_MS=400`: ожидание ввода на статических экранах периодически завершается без события; такие тайм-ауты **не** двигают курсор меню, не меняют поля и не вызывают установочные команды.
- `SCREEN_RESYNC_SECONDS=8`: периодический `redrawwin()` повторно отправляет весь виртуальный экран. Это восстановление, а не `erase()` по таймеру: для пользователя нет постоянного очищения/мигания.
- `Ctrl+L`: ручное принудительное обновление через `clearok(True)` при нестандартном поведении SSH-клиента.
- `KEY_RESIZE` и изменение `getmaxyx()` вызывают повторную раскладку с сохранением текущего шага/ввода/скролла; невозможность кратковременно отправить кадр не прерывает установку.
- В режимах `subprocess.Popen` опрос **остаётся неблокирующим**; сохранение журнала в `/root` и сбор вывода продолжаются независимо от доступности экрана.
- После закрытия потокового экрана восстанавливается ограниченное ожидание ввода (вместо необратимого `nodelay(False)`).

## Контроль и ограничения

Добавлены `tests/test_r36_terminal_resume.py`, в том числе настоящий PTY с отключённым пользовательским вводом, `Ctrl+L`, `SIGWINCH` и проверкой непрерывного вывода тестового дочернего процесса. Не запускаются установочные операции или изменения VPS.

Это исправляет **потерю отрисовки при живом SSH**. Оно не может восстановить полностью разорванное SSH-соединение или локальную ошибку видеодрайвера клиента. На реальной VPS перед установкой обязателен snapshot и аварийная консоль провайдера. Для длительной установки можно использовать проверенный постоянный SSH-сеанс; не полагаться только на окно терминала.
