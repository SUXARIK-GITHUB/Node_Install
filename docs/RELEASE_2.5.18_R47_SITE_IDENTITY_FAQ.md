# Node Install 2.5.18 r47 — доменная идентичность и полезные FAQ сайтов (STAGING)

Дата: 07.11.2026. Источник: полный ZIP r46. Статус: **INCOMPLETE_STAGING_ONLY**.

## Контекст и технический вывод

В архиве уже были 120 самостоятельных тем (12 исходных, 96 каталожных, 12 signature), 600 HTML-страниц для rich-публикации, локальные CSS/SVG, CSP и закрытый Nginx allowlist. Генератор r46 использовал повторяющиеся общие ответы на странице вопросов у 96 тем. На публичных страницах отсутствовали `rel=canonical` и связанная с доменом информация Open Graph. Стандартный статический сайт может иметь эти атрибуты без JavaScript и запросов к третьим сторонам.

Ни один сайт сам по себе **не скрывает IP, SNI или статистику VPN-трафика**. Доступность через ТСПУ зависит от конкретного оператора, региона, протокола и времени. Установленный REALITY тоже нельзя признать нераспознаваемым только по рендеру сайта. См. документацию Xray REALITY: https://xtls.github.io/en/config/transports/reality.html и исследование DPI в России: https://www.hrw.org/report/2025/07/30/disrupted-throttled-and-blocked/state-censorship-control-and-increasing-isolation.

## Что изменено

1. `scripts/site_metadata.py` — единственный локальный генератор безопасных доменных metadata. Разрешены ровно четыре публичных пути (`/`, `/journal.html`, `/about.html`, `/questions.html`), проверенный FQDN. Для страницы 404 — `noindex,follow`, без canonical/OG URL. Все значения HTML-экранируются, внешние скрипты, фоновые запросы и зависимости не добавлены.
2. Во всех трёх семействах шаблонов на *опубликованных* страницах создаются согласованные `canonical`, `og:url`, `og:title`, `og:description`, `og:site_name` и `og:type`. Домен вставляется **при штатном рендере по домену текущей ноды**, а не берётся из preview-снимка.
3. У 96 каталожных тем `questions.html` теперь содержит три тематических вопроса по собственным материалам каждой темы; ответы берутся из проверенных текстов этой темы. Общие заявления о регистрации и аналитике остаются на странице «О проекте», где они относятся к поведению сайта.
4. Страницы `journal.html`, `about.html`, `questions.html` каталожных тем получили собственные тематические описания вместо одинакового SEO-сниппета. 12 signature-тем сохранили дизайн и отдельные тексты, но имеют различные описания публичных разделов.
5. Для встроенных SVG каталога и signature-тем уточнены смысловые подписи на фактическом языке сайта; у signature-тем исправлены языковые подписи навигации и sitemap.
6. `scripts/site_audit.py` теперь строго проверяет canonical/OG у каждой публичной страницы, отсутствие чужого или preview-домена и правильность `noindex` на 404. Сохраняются прежние запреты на скрипты, формы, удалённые файлы, подозрительный CSS, небезопасные ссылки и неправильные якоря.
7. Пересобраны локальные снимки **564 HTML-файлов** (540 каталожных + 24 исходных), без изменения CSS, маршрутов, иконок и общего макета. `robots.txt` и `sitemap.xml` сохраняют свой контракт.
8. Добавлено 8 отрицательных и позитивных регрессионных тестов. В упаковку добавлены новый локальный helper, тест и этот документ; проверка r47 также наследует уже существующие статические проверки r40–r46.

## Чего не меняли

`install.sh`, Xray/REALITY, RemnaNode, transport, VPN-профили, SSL/CA, Nginx, systemd, Docker, SSH/UFW, nftables, DNS, каскад, правила доступа и транзакции `site-install`/`site-change`/`site-rollback` **не изменены**. Подмена внешнего SNI, активные протокольные пробы, необоснованная подстройка ClientHello или изменения ключей не выполнялись. Это изменение **качества публичного сайта и контроля его целостности**, а не проверенное средство обхода ТСПУ.

## Публикация и откат на собственной staging VPS

1. Сделать snapshot хостера и проверить аварийную консоль, DNS и SSL. Нельзя обновлять установленную production-ноду только заменой файлов архива.
2. Для уже законченной **staging**-ноды выбрать тему в штатном `site-manager` и применить `change` с подтверждением `STAGING` и полным доменом. Это сохраняет Nginx, REALITY и ключи, использует существующую транзакционную публикацию. Новая версия генератора действует только при таком явном действии.
3. Проверить `nginx -t`, `vkarmani-selfsteal-check`, сертификат, `GET /`, `GET /questions.html`, `GET /journal.html`, `GET /missing-path` (404), содержимое `canonical`, `og:url`, `robots.txt`, `sitemap.xml`, реальный HTTP/2, CSS, мобильное отображение и отсутствие сторонних запросов.
4. При ошибке сайта использовать штатный `site-rollback`. При сетевом или системном сбое восстановить snapshot VPS. Не делать ручной reset UFW или переподписывать REALITY-ключи ради отката HTML.
5. Отдельно выполнить реальные клиентские тесты из двух различных сетей на своих нодах, включая доступность HTTPS, панель Remnawave и отсутствие непредусмотренного DIRECT; сохранить только обезличенные результаты. **Даже успешные результаты не гарантируют устойчивость к будущим блокировкам.**

Пока нет live evidence с операторских сетей, релиз остаётся `INCOMPLETE_STAGING_ONLY`. Редакционная и семантическая корректность не доказывает «невидимость» для ТСПУ/РКН.
