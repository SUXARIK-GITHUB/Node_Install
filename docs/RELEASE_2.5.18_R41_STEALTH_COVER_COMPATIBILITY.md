# Node Install 2.5.18 r41 — сайт по умолчанию и проверка скрытности

**6 ноября 2026.** Основа: полный проверенный архив r40. Состояние: `INCOMPLETE_STAGING_ONLY`. Изменения **не применялись** к рабочей VPS/Remnawave Panel. Это диагностический и установочный релиз, **не подтверждение защиты от DPI**.

## Цель и реализованное

1. **Каталог по умолчанию для новой Ordinary-ноды.** После выбора Ordinary и до изменения ОС проверяется весь манифест полного ZIP. Если архив содержит `111-atlas-docs` и проходит `scripts/verify_release.py`, автоматически выбирается готовая многостраничная тема. Публикация через **существующий** `scripts/staging_web_deploy.py site-deploy --rich-pages` только после `INSTALL_COMPLETE`; сохранены её журнал транзакции, проверки и откат. Указанный администратором `--site-theme` имеет приоритет. Для Entry/Exit, существующей/незавершённой установки и сценария `install.sh` **без полного ZIP** не вводится новая обязательная зависимость от каталога. Неверный манифест полного комплекта останавливает новую установку до изменения хоста. Ошибка необязательной публикации после commit сообщает о частичном результате и отменяет автоперезагрузку; rollback выполняет старый движок.
2. **Резервный встроенный сайт без «скоро открытие».** В `vk_write_site_tool` сохранены четыре композиции, генерация статических ресурсов, seed, атомарная публикация и откат. Удалены заявления «сайт в разработке», «демонстрационный макет» и другие признаки заглушки. Это редакционные материалы, **не вымышленные компании**, не обещания услуг, не перенаправления к VPN.
3. **Ограниченная нагрузочная проверка TLS.** `scripts/stealth_external_audit.py --parallel {2,3,4}` делает не более четырёх одновременных обычных TLS 1.3 соединений **к одному явно указанному собственному IPv4**. Возвращает агрегированные числа успешных рукопожатий, диапазон и медиану задержек и согласованность протокола, ALPN и cipher. Не передаёт REALITY-ключи; отсутствие ошибок **не подтверждает** устойчивость параллельного REALITY ClientHello. Без `--parallel` остаётся поведение r40; флаг `--confirm-owned-endpoint` обязателен.
4. **Сравнение r40/r41.** `scripts/stealth_report_compare.py` читает два уже созданных обезличенных отчёта, не подключается к сети и показывает изменившиеся проверки. Признаки DNS/TLS/HTTPS сравниваются **без** утверждения о DPI-устойчивости. Запрещены ссылки, некорректный JSON, неизвестные имена проверок, специальные файлы и слишком большие отчёты.
5. **Проверка связки Remnawave Host → клиент XHTTP.** `integrations/xhttp_subscription_audit.py` **только читает** серверный закрытый `profile-xhttp.json` и клиентский JSON или **один** `vless://` URI в файле `0600`. Проверяет XHTTP/REALITY, отсутствие Vision, SNI, публичный ключ, ShortID, host, path и режим. Дополнительно сигнализирует о спорных fingerprint, принудительных режимах XHTTP и явных маршрутах `direct` в полном клиентском JSON. Значения секретов, домена, IP и URI в выводе не печатаются. `STATIC_MATCH` означает только совпадение полей, **не** успешное подключение или отсутствие утечек.
6. Дополнен аудит запрещённых фраз публичных сайтов; добавлены изолированные тесты на отказы/совместимость.

## Безопасные команды для staging

```bash
# Проверка самого архива, без установки
python3 scripts/verify_release.py --root .
python3 scripts/site_audit.py --rich
bash -n install.sh

# После тестовой установки; выполнять с другого своего хоста
# Заменить HOSTNAME и PUBLIC_IPV4 действительными значениями своей ноды.
umask 077
python3 scripts/stealth_external_audit.py \
  --domain HOSTNAME --ip PUBLIC_IPV4 --confirm-owned-endpoint --parallel 4 \
  > /root/https-r41.json

# Read-only сравнение с аналогичным ранее полученным отчётом
python3 scripts/stealth_report_compare.py /root/https-r40.json /root/https-r41.json --strict

# Проверка собственного client export после настройки Hosts/подписок в Panel.
# Нужен конфиденциальный JSON клиента ИЛИ отдельный файл с одной VLESS-ссылкой.
chmod 0600 /root/client-export.json
python3 integrations/xhttp_subscription_audit.py \
  --server /etc/vkarmani-node/profile-xhttp.json --client /root/client-export.json
```

Рекомендуется **не сохранять и не передавать** живой клиентский URI в журналы или обращения поддержки. В полной конфигурации Remnawave Host ручной экспорт может отличаться от runtime inbound; если нет точного client export, проверка не даёт заключения о совместимости. Сборка **не создаёт** пользователей, Hosts и подписки в Remnawave и не меняет active inbound.

## Обязательная staging-приёмка, до production

- Provider snapshot и подтверждённое восстановление, проверка аварийной консоли; **не** заменять файлы предыдущей версии на рабочей ноде вручную.
- Чистая Ordinary VPS: обычная установка из **полного ZIP** публикует `111-atlas-docs`; `--site-theme` переопределяет; standalone `install.sh` оставляет статическую редакционную fallback-страницу; повторный запуск и каскад не получают автопубликацию.
- HTTPS: сертификат/цепочка, HTTP/2, неизвестный SNI/Host, HEAD, 404, TLS 1.2/1.3, недоступность и перезапуск Unix socket, сертификат после renewal, `nginx -t` перед reload.
- **Отдельный живой REALITY**-клиент: полный постквантовый ClientHello и его TCP-сегменты, успешное соединение при одиночном и умеренно параллельном подключении; получить pcap лишь на своём тестовом сервере и без пользовательских данных. Ограниченный TLS-аудит выше этого не делает.
- Для XHTTP дополнительно: импорт профиля в Remnawave Panel, Hosts и полная клиентская подписка, фактические Xray-core/клиентские версии, fingerprint, поток, UDP/443, DNS, IPv6 и отсутствие нежелательного `direct` fallback. Ни один из этих пунктов нельзя считать пройденным по одному `STATIC_MATCH`.
- Проверка после reboot, сетевого обрыва и rollback. При отказе необязательной публикации восстановить сайт штатным `--site-manager rollback --confirm-staging` после изучения receipt; при повреждении ОС — provider snapshot.

## Область изменений и ограничения

**Не менялись:** RAW/REALITY транспорт, XHTTP `mode=auto` server template, ClientHello uTLS, Nginx, Docker, UFW, SSH, Node API, IPv6, каскад, ключи, миграции, systemd и продуктовые функции. Для новых Ordinary из полного ZIP изменился **выбор темы по умолчанию**, а не слушатель TCP/443. Если полного исходного набора нет, работает встроенный редакционный сайт без внешних зависимостей. Системных измерений реальной сети не выполнялось.

Успешная проверка конфигурации или обычного TLS не означает невидимость от DPI, защиту реального IP, отсутствие fingerprint или поддержку всех клиентов. Автоматического включения XHTTP/FinalMask нет. Историческая известная нестабильность таймингов теста r36 и проблема статуса nftables из аудита r39 не исправлялись как не относящиеся к этому релизу.
