# Node Install 2.5.18 r31 — этап 2/2: задачи 6–9

**Сборка: `20261106-r31-terminal-ui-journal-keys-exit`, статус `INCOMPLETE_STAGING_ONLY`.**
Полный пакет поверх проверенной r30, без новых демонов/контейнеров/зависимостей и без миграции работающей VPS. Установка на production не проверена. Все изменения этапа локализованы в `scripts/terminal_ui.py`, проверках и операторской документации. Базовые shell-команды и политика SSH/UFW/Docker/Nginx не менялись.

## 6. Терминальное оформление

- Все экраны `curses` используют единое оформление: глубокий графитовый фон, зелёный и светлый текст, яркий заголовок, тонкие разделители, контрастные активные карточки, полноэкранная рамка с внутренними полями. Компактные окна и 16-цветные терминалы имеют упрощённый вариант, размер и края проверяются до вывода.
- `menu`, `field`, `message`, `logs` и экран ключей используют общую геометрию. Контент не должен затирать боковую рамку или последнюю колонку терминала. Обновление только по клавише, изменению лога или размеру окна; нет постоянной слепой очистки терминала.
- **Ограничение терминала:** программа через SSH **не может установить шрифт, физический размер символов или сглаживание в MobaXterm/Windows**. Эти параметры выбираются пользователем в настройках клиента (или оконного терминала). Получаем визуально близкую *терминальную* реализацию референсов, не HTML/CSS-пиксельную копию. В `TERM=dumb` остаётся функциональный текстовый fallback.

## 7. Сохранение живого журнала в `/root`

- Когда из TUI начинается **новая установка**, до вызова `install.sh` создаётся `/root/node-install-YYYYMMDD-HHMMSS-PID-NN.log`. Права `0600`, владелец `root`; `/root` должен быть приватным (`0700`). Существующий журнал никогда не перезаписывается, ссылки и необычные типы файлов отклоняются. Новый журнал содержит **весь полученный stdout/stderr установщика после очистки ANSI и редактирования известных секретных полей**, включая поздние ошибки, как только строки поступают в TUI. `fsync` выполняется во время установки и при завершении.
- Вывод терминала остаётся живым, раскрашивается и доступен с прокруткой. Диск ограничен 64 MiB на один файл, при превышении журнал отмечается как усечённый. Если файл не удалось создать, **установка не стартует**. Если запись отказала уже во время изменения VPS, процесс не прерывается; UI показывает предупреждение о неполном файле.
- Запись производится **только в режиме мастера TUI** (`bash install.sh --menu`), а не при прямом `--install-direct` или read-only диагностике. Это предотвращает неожиданные изменения всех старых CLI-сценариев. Административные команды в «Управление» также не создают файлов журнала установки.
- Текстовые редактирования секретов — дополнительная защита, а не гарантия скрытия произвольных секретов в нестандартном выводе. Никогда не публикуйте эти root-only логи без проверки содержимого. `reality-keys.txt` в них не копируется.

## 8. Экран ключей и копирование

- После итогового экрана (успешный результат, в том числе частичный с кодом 20/21 при доступном файле) открывается **REALITY / КЛЮЧИ УСТАНОВКИ**. Тот же экран повторно открывается через «Управление нодой → REALITY — ключи».
- Программа только читает `/root/reality-keys.txt` при строгих проверках `root:0600`, обычный файл, `nlink=1`, не symlink, максимальный размер 32 KiB. Все поля (`Domain`, `PrivateKey`, `PublicKey`, `ShortID`, `Reality mode`, `Reality target`, `xver`, `flow`, `minClientVer`, `serverName/SNI`) и заголовок показываются как список.
- `PrivateKey` по умолчанию скрыт; `V` раскрывает/скрывает поле на экране. Стрелками выбирается строка, `Enter` **запрашивает** копирование только её значения через стандарт OSC 52 в SSH-клиент. Не выполняется `cat` поверх curses, значения не пишутся в журнал или в argv/env. Терминал может запретить OSC 52 — успешная вставка **не подтверждается** приложением. В этом случае можно раскрыть выбранное значение и скопировать выделением мышью в доверенной консоли. После показа или копирования `PrivateKey` не делайте публичные скриншоты и очистите буфер обмена.
- При отсутствии или небезопасном файле UI показывает отказ, не создаёт новый ключ и не ослабляет права.

## 9. Кнопка выхода из установщика

В главное меню добавлен шестой пункт **«ВЫЙТИ ИЗ УСТАНОВЩИКА»**. Он возвращает `0` родительской интерактивной оболочке: SSH-соединение остаётся, если `bash ./install.sh --menu` запущен как дочерняя программа в уже открытом SSH-сеансе. `Esc`/`0` из *главного меню* также завершают интерфейс. При запуске как одноразовая удалённая SSH-команда после завершения удалённой программы сам SSH-клиент может закрыть соединение — это зависит от способа запуска, а не от curses.

## Проверки и ограничения

- Протестированы локально: отдельный переход в shell, размеры 55x17/58x22/80x24/85x29/132x39, права и уникальность журналов, отсутствие перехода к установке при отказе диска, потоковая редактированная запись, чтение и проверка файла REALITY, OSC 52 без реальной отправки клиенту, старые сценарии r27–r30, синтаксис Python/Bash и проверка ZIP/SHA-256.
- Не подтверждены: точная передача буфера в MobaXterm, шрифты MobaXterm, живой SSH/Ubuntu/Pty на VPS, защищённость локального компьютера, полная установка, Nginx/Docker/UFW/Panel, скорость/квоты, реальный reboot и устранение `VKARMANI_SELFSTEAL_CHECK` / кода 20.
- Для тестирования на VPS нужен новый отдельный staging-сервер, работающая консоль провайдера, проверенный snapshot и верификация архива. После установки проверить `ls -l /root/node-install-*.log /root/reality-keys.txt`, доступ из `sudo` и отсутствие секретов в файле журнала; никуда не пересылать эти файлы без очистки. Откат системных действий — восстановление snapshot. Эта версия не устанавливается поверх действующей Node автоматически.
