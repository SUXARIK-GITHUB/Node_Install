# 🧪 Отчёт о проверках Node_Install 2.1.0

Дата: **30 сентября 2026**. Основа — полный архив 2.0.3; исходный `install.sh` имеет SHA256 `22b9e50d736e6332d3ad3973d6e23b56ba7f4338a161ab2f118e226ef392c216`. До изменений заново выполнены **304 теста: PASS, 0 пропусков, 15.337 секунды**.

## Итог и повторяемость

**349 отдельных тестов: PASS, 0 пропусков — прежние 304 + 45 новых.** После завершения правок кода три отдельных инструментированных полных прогона завершились за **21.748 / 23.720 / 23.855 секунды**. Последний полный журнал: [tests_2.1.0.txt](evidence/tests_2.1.0.txt). Подготовка самого артефакта отражена в [RELEASE_VALIDATION.json](RELEASE_VALIDATION.json); финальная проверка распакованного поставочного ZIP дополнительно фиксируется во внешнем `Node_Install_2.1.0_RELEASE_VALIDATION.json`, без изменения хешей уже упакованных файлов.

**Не каждый запущенный опыт был успешным.** Первый новый прогон выявил устаревшие mocks в тестах пакетного этапа после переноса repository preflight. Они исправлены, прежние отрицательные APT-сценарии сохранены. Визуальный тест нашёл реальное переполнение страницы на ширине 768 px (778 px scroll width); исправлена ширина декоративного блока и заново проверены все размеры. Один пакетный запуск повторов был прерван лимитом инструментальной среды и не засчитан как PASS. Диагностика с faulthandler, три завершённых полных повтора и **15 дополнительных повторов прежнего теста 128 проверок / 16 потоков** не воспроизвели зависание. Причину первого прерывания по неполному журналу нельзя достоверно отнести к коду проверяемого helper. Эти повторы не являются длительным soak test.

## Где и что действительно запускалось

Контейнер Debian 13, x86_64; Python 3.13.5, Bash 5.2, OpenSSL 3.5.5, Nginx 1.26.3, APT 3.0.3. Новый код использует стандартную библиотеку Python и существующие инструменты. Установщик целиком не запускался: системные SSH/UFW/GRUB, пакетный состав среды и сервер пользователя не изменялись.

| Область | Новых тестов | Фактическая граница |
|---|---:|---|
| Очистка APT | 8 | Настоящий `apt-get clean` с изолированным cache и POSIX lock; timeout/потомки; отсутствие пропуска обязательной приёмки; приватный атомарный статус |
| Ubuntu / Chrony | 13 | Точная матрица ID/version/codename/arch; реальные опции утилит этой среды; сохранение NTS/sources; запрет неизвестных flags; ошибка validate/rollback. Ответы chronyd имитированы |
| Сайт / backup / rollback | 15 | Сохранность файлов VPN, отказ до изменений при плохом state, права/ссылки/traversal, ENOSPC/EIO, сигнал, возврат, конфликт поздней правки оператора |
| Сайт через настоящий Nginx | 3 | PROXY protocol + TLS 1.3 + HTTP/1.1/HTTP/2, HTML/CSS/SVG и MIME; атомарная замена и возврат без нового PID; 48 проверок через 8 потоков |
| Диагностика ресурсов | 6 | Парсинг CPU/PSI/TCP/reset, отсутствие ложных показателей; настоящий отдельный read-only CLI на текущей среде |

Сохранённые тесты включают настоящий PTY со скрытым длинным ключом, локальный TLS API, HTTP/2 flow control на страницах 96/128 KiB, восстановление Nginx после SIGKILL, 128 проверок через 16 потоков, round-trip tar backup и пять настоящих APT solver-сценариев с локальными синтетическими метаданными. Сценарии Docker/update/rollback используют имитацию Docker, а не настоящий daemon. Firewall проверяется по фикстурам; правила на хосте тестов не применяются.

`48` или `128` проверок сайта — **не число одновременных VPN-пользователей и не Mbps benchmark**. При двух TLS-сессиях на проверку число TLS-сессий удваивается; это не отдельные пользовательские соединения VPN.

## Браузерная проверка

Chromium 144.0.7559.96, Playwright. Проверены ширины **320, 375, 390, 620, 768, 900, 1024, 1440, 1920** px, отсутствие горизонтального переполнения и пересечения заголовка с описанием, reduced motion, отсутствие scripts. [Машиночитаемый отчёт](evidence/browser_2.1.0.json).

Браузерная политика среды запретила навигацию по HTTP/file URLs. Поэтому только для **визуальной** проверки HTML и идентичный CSS переданы в память браузера. Сетевой маршрут и загрузка assets этим способом не проверены; фактические HTTP/MIME/TLS-проверки файлов выполнены отдельно настоящим Nginx. Скриншоты desktop/mobile просмотрены. Safari, Firefox и физические мобильные устройства не тестировались. Шрифты системные и не включены в архив.

## Сохранность архитектуры

Сравнены байты исходных и новых фрагментов: `make_keys_profile`, `validate_profile`, Compose, Nginx HTTP и Selfsteal-конфиги, sysctl, Fail2ban jail, TLS API checker и Selfsteal checker. Они идентичны; хеши в [unchanged_policy_2.1.0.json](evidence/unchanged_policy_2.1.0.json). Это проверка исходников, не доказательство неизменности неосмотренного сервера.

Сохранены три вопроса и их порядок, парольный SSH, API source restriction, IPv4-only, VLESS RAW REALITY и собственный Selfsteal. Новый `--update-cover` не является общей миграцией 2.0.3 в 2.1.0 и не обновляет системные helpers старой ноды. Для рабочего VPN полный install ради оформления не нужен.

## Что не проверено и не обещается

**Нет полного install/reboot/restore на Ubuntu 26.04, 24.04 или arm64.** Здесь не удалось получить отдельную VM/rootfs 26.04 и не запускались Python 3.14, настоящее NTS/Chrony, systemd259/OpenSSH10.2, Docker daemon/Compose/Xray, настоящий UFW/Fail2ban, ACME или клиентская подписка пользователя. Подготовленный CI userspace 26.04 ещё не выполнялся на GitHub и не проверяет ядро/GRUB даже при будущем успешном запуске.

Не выполнялись длительный нагрузочный тест, реальные OOM/отключение питания, тесты каналов разных стран, оценка устойчивости к DPI или гарантированного обхода IP-фильтрации. Изменённая страница не делает узел нераспознаваемым. Нулевой риск, ускорение в процентах, число поддерживаемых клиентов и безусловная работа всех хостерских образов не заявляются.

Пользователь подтвердил работающий VPN версии 2.0.3 на Ubuntu 24.04. Это не новое испытание 2.1.0. Перед тиражированием нужен отдельный пилот 26.04 с snapshot/консолью, собственной панелью, проверенным digest, reboot, renew, реальным RAW REALITY-клиентом и контролируемым rollback.

## История и воспроизведение
