# Node Install 2.5.18 r40 — HTTPS-прикрытие и диагностика обнаруживаемости

**Дата:** 2026-11-06. **Тип:** только staging, `INCOMPLETE_STAGING_ONLY`. **База:** исходный полный ZIP r39; сервер и текущая ОС не менялись.

## Цель и границы

Устранить только проверяемые общие признаки в опубликованных сайтах и расширить диагностику HTTPS-поведения Selfsteal. Никакой гарантии «невидимости» здесь нет: TLS/QUIC fingerprint, размер пакетов, IP-адрес, ASN, время соединений и поведение TLS 1.3 после handshake могут быть видны наблюдателю. Исследование методов обнаружения оформлено в ранее подготовленном отдельном отчёте; выводы для r40 применяются консервативно.

## Что действительно изменилось

1. `scripts/cover_variants.py` — обновлён статический контент 12 тем. Вместо общих фраз об ознакомительном или демонстрационном характере используются сведения по соответствующей теме. Не добавлены адреса компаний, персональные данные, внешние скрипты или трекеры.
2. `scripts/site_catalog.py` — обновлён текст 108 тем и CSS. Убраны комментарии, выдающие общую природу генератора; индивидуальные CSS-свойства привязаны к детерминированной теме и реально используются для оформления, а не для встраивания скрытых маркеров.
3. `scripts/signature_sites.py` — скорректированы формулировки FAQ. Перегенерированы все 120 каталожных сайтов: 12 в `cover-variants/` и 108 в `site-catalog/`. Комплект 600 HTML-документов и 1080 ресурсов в rich-каталоге проходит offline-аудит.
4. `scripts/site_audit.py` — проверка `PUBLIC_PLACEHOLDER_COPY` запрещает известные повторяющиеся фразы-заглушки в публичной странице. Проверки CSP, HTML, SVG, CSS, локальных ссылок и количества ресурсов сохраняются.
5. `integrations/selfsteal_runtime_probe.py` — опциональный `--extended`: четыре проверенных TLS-соединения к **собственному локальному Unix-сокету**, HEAD, 404 и неизвестный Host. Идентификаторы или сертификаты пользователей не сохраняются. В `integrations/selfsteal_chain.py` расширенная проверка включена при запуске существующего read-only Selfsteal verify. Обнаруженные отличия — `REVIEW`, не `PASS`.
6. `scripts/stealth_external_audit.py` — **новый** read-only клиент для публичного адреса пользователя: TLS 1.2/1.3 и доверенная цепочка сертификата, ALPN, 404, HEAD, некорректный Host, SNI, DNS A/AAAA и HTTP-редирект. Утилита не перебирает адреса, порты или пути, не следует внешним редиректам, не сохраняет заголовки, cookies, IP-адрес в отчёте и не отправляет REALITY-ключи.
7. `tests/test_r40_stealth_cover_and_probe.py` — сетевые проверки имитируются функциями, а локальный Unix TLS проверяется через временный сертификат OpenSSL. Никаких реальных production endpoints в тестах.

## Как запускать — только на собственных серверах

Offline проверка без изменений системы:

```bash
python3 scripts/site_audit.py --rich
```

Проверка локального Selfsteal Unix-сокета после штатной тестовой установки (путь и домен подставляются из **своего** окружения; `--proxy-v1` обязателен для xver=1):

```bash
python3 integrations/selfsteal_runtime_probe.py --domain node.example.com \
  --socket /run/vkarmani-selfsteal/nginx.sock --proxy-v1 --extended
```

Проверка публичного HTTPS-порта и DNS **своей** тестовой VPS (с другого контролируемого устройства с выходом в интернет):

```bash
python3 scripts/stealth_external_audit.py --domain node.example.com \
  --ip 203.0.113.123 --confirm-owned-endpoint
```

`node.example.com` и `203.0.113.123` — **нерабочие значения-примеры** (документационные диапазоны). Замените на свой действительный публичный IPv4 и имя. Программа намеренно отвергает приватные, зарезервированные и неглобальные адреса. При вариантах nginx/TLS, не поддерживающих определённый необязательный протокол, результаты трактуются как `REVIEW` и анализируются вручную, настройки не изменяются автоматически.

`--strict` завершает аудит с кодом 2 при `FAIL` или если публичные проверки не все `PASS`. Общий `status=UNVERIFIED` **не ошибка**: замеры TLS 1.3 NewSessionTicket после handshake стандартная библиотека не доказывает и возвращает `UNVERIFIED`. `live_checks_status=PASS` не означает скрытность от DPI.

## Что намеренно не менялось

`install.sh`, основная конфигурация Nginx, режимы XHTTP/REALITY, fingerprint клиентов, Remnawave Panel/Hosts, Docker, маршруты каскада, данные, порты, SSH, firewall, пользовательский UI. Никаких сторонних сетевых или серверных сервисов. Внешние SNI и новые транспорты не включены по умолчанию: их реальная эффективность и совместимость не подтверждены. Изолированная ошибка статуса трафик-лимитов, отмеченная в r39 аудите, остаётся вне узкой задачи скрытности.

## Приёмочные проверки и ограничения

- Целостность ZIP и манифеста SHA-256: `python3 scripts/verify_release.py --zip FULL.zip`; отдельно проверяются права файлов в архиве.
- Синтаксис Bash: `bash -n install.sh`; компиляция Python и unit-тесты всего проекта, включая 120 rich тем.
- Стенд: проверить сертификат, оба TLS, неизвестный SNI, HEAD/404/Host, timeout/restart Nginx, недоступность сокета, смену домена, OpenSSL и альтернативные версии Nginx.
- Для реальной незаметности: запись pcap только на собственном стенде (TLS 1.3 tickets/records), независимый клиент из другой сети, проверка DNS/IPv6/UDP 443, Vision `direct` fallback, актуальные версии Xray/Remnawave/клиентов и откат после потери Selfsteal. Без этих испытаний нельзя утверждать повышение DPI-устойчивости.

## Безопасная публикация и откат

До установки: snapshot провайдера, подтверждение восстановления snapshot и аварийного доступа. На staging: документирование текущей конфигурации, проверка `nginx -t` до любого reload, тест HTTPS/REALITY с реальным клиентом, повторный тест после reboot. Для возврата к r39 используйте **сохранённый архив и процедуру rollback проекта** либо восстановление snapshot при затрагивании ОС. Не заменяйте файлы на работающей ноде вручную поверх checkpoint, их SHA может быть привязан к предыдущему релизу. Если не проходятся интеграционные проверки — релиз не публикуется и не развёртывается на production.
