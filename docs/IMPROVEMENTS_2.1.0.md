# Улучшения 2.1.0: причины, эффект, границы

Дата: 30.09.2026. Основа — полный архив 2.0.3 с SHA256 `install.sh` `22b9e50d736e6332d3ad3973d6e23b56ba7f4338a161ab2f118e226ef392c216`. Исходный набор 304 тестов повторно прошёл до изменений. Живой сервер пользователя не изменялся, GitHub не публиковался.

## Подтверждённые проблемы исходника

**Необязательный apt-get clean был обязательным перед финальной приёмкой.** Предыдущий пользовательский журнал показал rc=100 из-за блокировки кэша `unattended-upgrades`, а повторная установка закончилась нормально. Это гонка, не исправление от переустановки. Новый helper различает PASS, DEFERRED/LOCK_BUSY и WARNING/другие ошибки. Бюджет команды — 20 секунд плюс ограниченное завершение только её собственной группы процессов. Статус записывается атомарно, без сырого stderr. Очистка не отменяет обязательный `vkarmani-node-check`; ошибка самой приёмки по-прежнему запрещает INSTALL_COMPLETE. Тот же helper применяется в плановом cleanup.

Не удаляются lock-файлы, не завершаются чужие apt/dpkg, не отключаются security updates. Не делается `autoremove` или Docker prune. Другие ошибки очистки **не выдаются за занятую блокировку**. Неудачная запись статуса выводит предупреждение, а не скрывает проблему диска.

**Chrony сохранялся как пакет, но его конфигурация перезаписывалась.** Это теряло штатные sources/includes и NTS современной Ubuntu. Теперь исходные источники остаются; синтаксис проверяется до и после правки. Служба здесь не останавливается, файлы пытаются восстановиться при ошибке до перезапуска. Необычные launch flags требуют анализа вместо слепой замены. Timesyncd продолжает сохраняться, если уже установлен.

**26.04 отсутствовала в allowlist.** Добавлены точные OS/codename/architecture gates, cgroup v2 и проверка реальных опций утилит. Репозиторий Docker и общий пакетный план проверяются **до** смены SSH/UFW/GRUB. Это перенос проверки раньше, не автоматический откат любых пакетных операций и не гарантия от последующего сетевого сбоя. Успешный план не фиксирует все версии пакетов навсегда.

## Меньше лишних внешних признаков — без обещания невидимости

Свой домен/SNI, реальный сертификат и локальный Selfsteal сохранены. Новая страница убирает фиктивный аккаунт/рабочее пространство и рассказы о шифрованных подключениях. На странице нет технических названий installer/VLESS/Remnawave и внешних зависимостей. В коде Nginx уже есть `server_tokens off`; это не скрывает всю TLS/HTTP-реализацию.

Не добавлены случайные TLS curves, глобальная фрагментация, фиксированный fallback rate limit, смена transport или неизвестный «анти-DPI» бинарник. В upstream REALITY предупреждают, что fallback limiting сам создаёт признак. Клиентский `fingerprint` находится в клиентской конфигурации, не задаётся sysctl на сервере. Параметры Host/клиента требуют отдельной проверки; установщик не переписывает работающий профиль через панель.

Публичный шаблон сайта всё равно можно узнать; небольшой выбор декоративных цветов не является криптографической защитой от корреляции. SNI/сертификат/DNS и один общий домен также не следует считать секретом. Страница не может сделать доступным IP, пакеты к которому не достигают VPS. Открытый парольный SSH сохранён по явному требованию проекта; Fail2ban не делает украденный пароль безопасным.

## Скорость и стабильность: сначала наблюдать причину

BBR/fq, MTU black-hole probing и ограничение журналов уже есть. Их параметры не изменены без измерения. Для нового read-only среза:

```bash
sudo bash install.sh --diagnose-resources
sudo bash install.sh --diagnose-resources --seconds 5
```

Вывод: дельты TCP retransmissions/timeouts/listen drops, OOM/swap counters, CPU busy/iowait/steal, PSI, доступная память, свободный диск/inodes и ограниченная часть состояния RemnaNode. Нет списка соединений, IP клиентов, environment контейнера, секретов и автоматических изменений.

`busy_percent` — доля не-idle и не-iowait времени, **включая steal**; steal показан отдельно. Метрики относятся ко всему хосту, не только VPN. Сброс счётчика даёт `null`, а не отрицательные потери. Не вычисляется выдуманный «процент потерь VPN» из RetransSegs. PSI при отсутствии поддержки равен null. Фоновая служба или таймер не добавлены; команда запускается только оператором.

Практический следующий этап: отдельный idle и load срез, реальный клиентский download/upload и длинное соединение с конкретного оператора. Только после этого решать, что ограничивает скорость: CPU/steal, память/swap, очередь, конечный сайт, маршрут или канал. Автоматическая смена MTU, offload, root qdisc, TCP buffers или BBR-версии в этот выпуск не входит. Нет заявленного прироста Mbps или числа пользователей.

## Что не меняется

Ровно три вопроса, IPv4-only, парольный SSH без постоянного IP-allowlist, UFW/Fail2ban, API только с IPv4 панели, RAW REALITY, прежние ключи и схематичный profile template, host networking с read-only Selfsteal mount, отсутствие NET_ADMIN по умолчанию, правила обновления image digest, отсутствие автоперезагрузки по умолчанию. Никаких новых production зависимостей.

Внешние проверки, назначение профиля/Host/Squad, корректность клиента и контроль хостера остаются отдельными. Полной автоматической миграции 2.0.3 → 2.1.0 нет; для работающей 2.0.3 предусмотрена только отдельная операция сайта и запуск read-only resource snapshot новым файлом.
