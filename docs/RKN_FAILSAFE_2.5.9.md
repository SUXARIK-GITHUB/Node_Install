## Границы поведения и безопасности

**RKN и UFW — разные уровни.** При ошибке дополнительной RKN-интеграции базовая защита UFW должна сохраняться. При невозможности восстановить подтверждённый `before.rules`, cache, checkpoint или kernel ipset код возвращает ошибку `*_ROLLBACK_UNCONFIRMED`: не продолжать установку/обслуживание автоматически, исследовать через консоль хостера.

`RKN_FRESHNESS=STALE` означает, что проверенный список устарел (72 часа). В ответе `status` будет ненулевой exit code, но это **не команда отключать firewall**, стирать старые сети или открывать порты. Успешный `RKN_PANEL_SET_MATCH=PASS` подтверждает только сходство текущих записей kernel ipset с файлом конфигурации; сквозное управление панелью нужно проверять отдельно.

**Ночной рестарт** проверяет локальный контейнер и не заявляет здоровье панели, пользователей либо каскада. Повреждённый `maintenance-last.json` запрещено удалять автоматически, поскольку это может нарушить at-most-once; сохранить копию для разбора и только после анализа восстановить корректное состояние.

**Встроенные копии** Python helpers в `install.sh` побайтово идентичны отдельным файлам интеграции. Обе должны быть обновлены вместе.

## Read-only диагностика на изолированной staging VPS

Команды ниже не применяют новые правила; здесь используются реальные пути и имена из проекта. Исполнять на тестовом сервере с проверенным доступом в консоль провайдера:

```bash
sudo ufw status verbose
sudo systemctl is-active ufw.service
sudo systemctl status vkarmani-rkn-prepare.service --no-pager
sudo ipset list vkarmani_rkn_blk4
sudo ipset list vkarmani_rkn_pan4
sudo bash install.sh --rkn-status
sudo bash install.sh --maintenance-status
sudo nginx -t
```

При `RKN_DATA=DEGRADED`, `RKN_PANEL_SET_MATCH=FAIL`, `RKN_FRESHNESS=STALE/UNKNOWN` или `*_ROLLBACK_UNCONFIRMED` нельзя объявлять защиту рабочей на основании одного UFW `Status: active`. Не выполнять `--rkn-disable` на production для воспроизведения.

На VM дополнительно потребуются: snapshot и проверенный restore; проверка SSH из внешней сети; сетевые разрешения для IP панели и запреты посторонним; reboot с невалидным `config.json`, с отсутствующим ipset, с отказом UFW reload, с полным диском; сопоставление действующих правил и конфигурации перед/после.

## Полный релиз и ограничения

Сборка не предназначена для массовой установки или автоматического обновления production. В ней **не реализован двухсерверный каскад**, Nginx stream-мультиплекс для нескольких inbound и шесть новых сайтов; это остаётся незавершённой задачей ТЗ r2, а не скрытым PASS. Результаты unit/fault тестов не заменяют VM с systemd/UFW/ipset/Docker и сквозную проверку Remnawave Panel → Node → реальный VPN-клиент.

Проверенный выпуск должен отдельно публиковаться ответственным администратором после прохождения VM/staging и решения о rollout. Публичная GitHub-команда текущего `main` устанавливает старую опубликованную версию, не 2.5.9.
