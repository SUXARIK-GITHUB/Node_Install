# Node_Install 2.2.0 — собственный Selfsteal

Дата выпуска: 2026-10-02. База: полный Node_Install 2.1.3. Статус: локальные проверки пройдены; полноценный VPS-пилот не выполнен. Работа велась с исходниками и изолированными тестами, не с TECH или нодами пользователя.

## Решение и схема

```text
Internet TCP/443 → Xray RAW/REALITY
                   ├─ authenticated VLESS → прежний outbound
                   └─ TLS target / ordinary HTTPS → Unix socket → host Nginx
Internet TCP/80  → host Nginx → ACME либо fixed-domain HTTPS redirect
Panel TCP/2222   → прежний source-IPv4 firewall → RemnaNode management
```

REALITY-реализация, закреплённая в Xray 26.7.28, устанавливает соединение с target при handshake. Здоровый target — не просто декоративная страница. При этом успешно аутентифицированный VPN-payload не отправляется целиком через HTTP-vhost. Следовательно, отказ target может повлиять на новые подключения, но смена CSS не доказывает ускорения VPN. [Код и исследование](SOURCE_REVIEW_2.2.0.md).

HAProxy, iptables-фильтр SNI и Nginx stream proxy перед 443 не добавлены. Потребности в новом общем L4-разветвителе сейчас нет: используется один Xray и один собственный target. Nginx HTTP работает после TLS только в веб-ветви. Нельзя отключать REALITY ради внешнего TLS-терминатора L7. UFW остаётся единственным менеджером firewall, packet-level string matching по ClientHello не используется. Сеть, BBR, MTU, SSH, авторизация, схема контейнера и generated profile 2.1.3 не изменены.

## Контракты HTTP/TLS для новых установок

| Проверка или поведение | Контракт |
|---|---|
| Собственный домен на 443 | Прежний сертификат Certbot; проверяются TLS 1.3, HTTP/1.1 и HTTP/2 |
| REALITY target | `/dev/shm/nginx.sock`, `xver=1`, отдельный read-only host socket-каталог |
| Неверный или отсутствующий SNI | Серверный TLS-alert при Nginx >=1.19.4; на старом пакете — явно указанное ограничение |
| Неверный Host после TLS | HTTP 421 |
| Пишущие методы | HTTP 405; GET и HEAD сохранены |
| Неверный Host на 80 | HTTP 404, без redirect на собственный домен |
| ACME | Прежний HTTP-01 webroot; GET/HEAD, проверки отсутствующих файлов и symlink |
| Статика | Только root/index/robots/favicon/внутренний 404 и хешированные CSS/SVG |
| Случайные .env/config/dump в webroot | Не обслуживаются обычными URI; это не защита от изменения config пользователем root |
| Symlink | `disable_symlinks on from=$document_root` для публикуемых файлов |
| Кэш HTML | `no-cache`, то есть повторная проверка актуальности |
| Кэш CSS/SVG | Семь дней, ETag/304; новым байтам соответствует новое имя |
| HTTP-защита | CSP, nosniff и Referrer-Policy, включая assets/304/404, без потери наследования |
| Ресурсы | Прежние body 1 MiB и header/body timeout 15 s; дополнительно send timeout 15 s и max_ranges 1 |

Синтаксис HTTP/2 адаптируется к Nginx 1.25.1+, а не копируется из нового пакета в старый. `ssl_reject_handshake` появился в 1.19.4. Старый пакет не заменяется сторонним: для Nginx 1.18 остаётся HTTP-отказ, возможна выдача собственного сертификата до него, а helper пишет `NOT_SUPPORTED_BY_LEGACY_NGINX`. Настоящий бинарник 1.18 локально не запускался; проверены ветвление и fallback-конфигурация на доступной 1.26.3.

Прежний `access_log off` сохранён; существующий error log остаётся. Не добавлены source-IP ban lists, лимиты подключений за CGNAT, HTTP/3/Alt-Svc, отдельная настройка OCSP stapling, новые TLS-группы, новые сертификаты или второй ACME-клиент. Фильтрация IP/ASN, особенности carrier DPI, CPU steal и проблемы MTU/UDP не исправляются HTML-страницей.

`send_timeout` ограничивает паузу между операциями отправки, а не полную длительность соединения. `max_ranges=1` ограничивает многочастные Range-ответы статического сайта, не VPN-трафик. Такой закрытый vhost рассчитан на наш встроенный сайт; он не является конфигурацией для произвольной CMS.

## Расширенный локальный helper

`vkarmani-selfsteal-check` проверяет:

- TLS 1.3, CA и hostname; при переданном ожидаемом leaf — его точный хеш;
- фактическую передачу ожидаемого index через HTTP/1.1 и HTTP/2;
- HEAD без тела, правильную Content-Length, защитные headers и кэш;
- локальные ссылки CSS/SVG, хеш имени, байты, MIME и ETag/304;
- robots, favicon и собственный 404; отрицательные URI, методы и Host;
- серверный отказ неверному или пустому SNI, когда это поддерживается;
- ограничения времени, размера и безопасного чтения файлов, без скрытого PASS при ошибке.

Вывод сохраняет `SELFSTEAL_TLS13_HTTP1_HTTP2=PASS` и отдельно показывает новые этапы. Отрицательный SNI-тест использует клиент без CA-проверки исключительно для подтверждения серверного TLS-alert. Обычные положительные проверки CA никогда не отключают. Timeout или простой EOF не считаются доказательством нужного SNI-отказа.

Сохранён прежний CLI общего checker. Внутренняя функция `check(extended=False)` остаётся для прежних test fixtures; установленный CLI вызывает `extended=True`. Автоматическое чтение runtime JSON из RemnaNode в этот выпуск не добавлено. Local target PASS не равен real VLESS client PASS. Существующая строгая проверка через локальный публичный 443 сохранена, но новые проверки assets выполняются на Unix-target, не через все внешние сети клиентов.

## Визитка

Четыре оригинальные встроенные вариации, стабильный случайный seed при первой разрешённой установке или обновлении, небольшой HTML/CSS/SVG без JS и внешних ресурсов. Старые assets и backup/rollback сохранены. [Подробности](COVER_SITE.md). Различные оформления не являются доказательством скрытности или победы над DPI.

## Развёртывание и откат

На существующих нодах **не выполнять полную переустановку или обычный повтор как миграцию**. Он вызывает прежний установленный checker. `--update-cover` обновляет только визитку и её state; новые Nginx/helper-файлы 2.2.0 на старую ноду не переносит. Обновление всей установленной части потребует отдельной проверенной транзакции: backup → apply → verify → rollback. Менять markers вручную или обходить policy нельзя.

Для новой canary VPS: проверенный snapshot, восстановление и консоль → проверка manifest → установка с `--no-reboot` для ручного окна → preboot/Nginx/target → новый парольный SSH-вход → назначения профиля и пользовательский тест → согласованный reboot → postboot, публичный HTTPS и клиент → наблюдение → только после этого следующие ноды.

Полный откат системной установки — проверенный VPS snapshot, не image-only откат и не запуск 2.1.3 поверх 2.2.0. Не пересоздавать RemnaNode или Nginx ради дизайна. В Certbot renewal-hook сохранены `nginx -t` перед reload и проверка обновлённого сертификата. Команды эксплуатации находятся в [OPERATIONS](OPERATIONS.md). Никакие операции на VPS или GitHub этим выпуском локальной разработки не выполнялись.

## Проверки и ограничения

[TEST_REPORT](TEST_REPORT.md) и [RELEASE_VALIDATION](RELEASE_VALIDATION.json) фиксируют результаты. Новые тесты используют настоящий локальный Nginx, Unix socket, TLS/HTTP2 и большой фрагментированный ClientHello, но не ядро Xray, не контейнер RemnaNode и не публичный Интернет-путь.

Полный цикл на поддерживаемых Ubuntu/Debian, старый бинарник Nginx, arm64, ACME в реальном окружении, panel/client и reboot требуют отдельной приёмки. Производительность под клиентской нагрузкой и срок до блокировки IP не измерялись. Рабочие live-профили и REALITY-ключи пользователя не изменялись.
