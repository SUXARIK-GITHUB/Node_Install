# Node Install 2.5.18 r37 — Blocky / HaGeZi Normal (STAGING ONLY)

## Что сделано

Необязательный локальный DNS-фильтр рекламы на базе Blocky **v0.35.0** и списка **HaGeZi Multi Normal** в wildcard-формате. При выборе «Включить» установщик сам скачивает и проверяет бинарный релиз по SHA-256, загружает список, создаёт строго локальный DNS, запускает systemd-службу и таймер ежедневного обновления, проверяет разрешение обычного домена и блокировку тестового домена. Установка выполняется только по выбору администратора. По умолчанию функция отключена.

**Важное ограничение:** Remnawave Panel управляет рабочим Xray Config Profile. У Node Install нет полномочий менять профиль в удалённой Panel, а значит включение Blocky **не гарантирует автоматическую фильтрацию DNS у VPN-клиентов**. Фильтруются только запросы, отправленные к `127.0.0.1:15353` на соответствующей VPS. Для клиентской фильтрации DNS должен быть направлен к этому резолверу в управляемом Panel профиле и реально проверен через VPN-клиента. Включение/выключение Blocky не изменяет Panel, подписки, Xray JSON, Docker, Nginx, UFW, SSH, `/etc/resolv.conf` или сетевые маршруты. В каскаде устанавливать только на Exit; на Entry операция запрещена.

## Установка и управление

В меню `УПРАВЛЕНИЕ NODE → Блокировка рекламы · Blocky` доступны **Состояние**, **Включить**, **Выключить фильтрацию**, **Обновить списки**, **Проверить DNS**. В мастере новой Ordinary/Exit-ноды имеется необязательный переключатель в дополнительных настройках; Blocky устанавливается только после успешного кода 0 основного установщика. При кодах 20/21 и других ошибках установка Blocky откладывается и не меняет частично настроенную ноду.

CLI (вызов из полного исходного архива):

```bash
sudo bash install.sh --adblock status       # только чтение
sudo bash install.sh --adblock enable       # явно включить, загрузить и проверить
sudo bash install.sh --adblock disable      # отключить ФИЛЬТРАЦИЮ, оставить DNS-службу
sudo bash install.sh --adblock update       # проверенная загрузка списка
sudo bash install.sh --adblock probe        # локальная функциональная проверка
```

### Автоматическая перезагрузка после опциональной установки

При выборе Blocky вместе с обычным авто-reboot в мастере установщик **не** назначает свою стандартную 30-секундную перезагрузку сразу после core. Сначала проверяет Blocky и загруженный список, затем безопасно назначает выбранный reboot через `systemd-run` с задержкой 45 секунд. Если Blocky не установился, `systemd-run` недоступен или установка закончилась частично, авто-reboot не назначается. Это предотвращает прерывание скачивания и оставляет время администратору проверить проблему. При отключённом в настройках reboot новый автоматический reboot не добавляется.

## Файлы и службы

| Компонент | Путь / назначение |
|---|---|
| Blocky binary | `/usr/local/libexec/node-install-adblock/blocky` |
| Обслуживание | `/usr/local/libexec/node-install-adblock/adblock.py` |
| Конфигурация | `/etc/node-install-adblock/config.yml` |
| Пример DNS для Xray | `/etc/node-install-adblock/remnawave-dns-example.json` — **только справочный файл**, не внесён в Panel |
| Список | `/var/lib/node-install-adblock/hagezi-normal.txt` |
| Предыдущий проверенный список | `/var/lib/node-install-adblock/hagezi-normal.previous.txt` |
| Служба | `node-install-adblock.service` (непривилегированный systemd DynamicUser) |
| Обновление | `node-install-adblock-update.timer` (ежедневно в 04:00, с разбросом до 45 мин) |

Только `127.0.0.1:15353` TCP/UDP. Публичный DNS-порт 53 **не открывается**, веб-панель и HTTP API не включаются. История доменов клиентов не сохраняется. Служба использует DoH-upstream Cloudflare/Google, DNS-кеш с ограничением числа записей, `NoNewPrivileges`, `ProtectSystem`, ограничения capabilities и фильтрацию по локальному файлу.

## Обновления списков

Источник: <https://raw.githubusercontent.com/hagezi/dns-blocklists/main/wildcard/multi.txt> (HaGeZi Multi Normal, совместимый с Blocky).

- Ежедневная загрузка только по HTTPS с максимальным размером; проверка заголовка HaGeZi, допустимого формата wildcard и числа записей (минимум 30 000; не более 30% расхождения от текущей версии).
- Обновление записывается атомарно; предыдущая успешная версия остаётся в `hagezi-normal.previous.txt`. Если GitHub недоступен или список недостоверен, прежний файл остаётся без изменений.
- Blocky перечитывает локальный список через `blocking.loading.refreshPeriod: 5m`. Никакой скрипт `curl | bash` не выполняется, скачанные домены не являются исполняемым кодом.
- Исполняемый файл Blocky закреплён на **v0.35.0**: проверяются официальные SHA-256 для Linux x86_64 и arm64. Обновления исполняемого файла **неавтоматические**, чтобы не менять работающее ПО без тестирования.

## Сценарии ошибок и откат

- Отсутствие системной ноды, неполный checkpoint, роль Entry, конфликт локального порта, неизвестная архитектура, чужие файлы/символьные ссылки, ошибка SHA-256, отказ DNS и ошибка systemd приводят к STOP.
- Включение записывает только новые файлы Node Install Adblock. При ошибке запуска возвращает старые файлы, предыдущее состояние службы и не меняет основной RemnaNode.
- «Выключить» оставляет DNS-сервер как обычный резолвер **без блокировки**, чтобы клиенты, уже направленные на него, не лишились DNS.
- Для аварийного восстановления после повреждения системных настроек ноды необходим ранее проверенный snapshot. Эта функция не выполняет очистку ОС.

## Известные ограничения

1. **Нет подтверждения фильтрации у VPN-клиентов без настройки Panel.** DNS-запросы с клиентского DoH/DoT могут проходить мимо Blocky; видео-реклама YouTube/других приложений часто использует общие домены и не убирается DNS-фильтрацией.
2. Надёжность разрешения доменов зависит от доступности выбранных внешних DoH; в условиях блокировок upstream возможна задержка или неработающий DNS. При первоначальном включении выполняется локальная проверка, но не тест реального VPN-клиента.
3. Список поступает из внешнего проекта без криптографической подписи каждой версии: сетевой TLS и валидация содержимого снижают риски, но не устраняют риск ошибочного правила.
4. Результат OFFLINE QA не равен полноценному запуску Blocky на Ubuntu. Необходимо отдельно проверить реальную загрузку бинарника, `systemctl`, DNS UDP/TCP, обновление timer, блокировку и производительность в staging VPS.
5. Не обещается отсутствие влияния на задержку: DNS-кеш снижает повторные запросы, но фильтрация/DoH добавляют время обработки DNS. VPN-throughput через Blocky не проходит.

## Приёмка перед production

Сделать snapshot, проверить восстановление, установить на staging VPS, включить только на Ordinary или Exit. Убедиться в loopback-only сокете, отсутствии открытого TCP/UDP 53, совпадении списка, работе `probe`, `status`, `disable`, `enable`, `update`, рестарте и обновлении после reboot. Подключить подходящий Remnawave Config Profile **контролируемо на тестовом профиле** и проверить DNS-запросы, веб-сайты, отказ Blocky и задержки с реальным VPN-клиентом. Если профиль не перенаправляет DNS на Blocky — статус клиентов остаётся `NOT_VERIFIED`, а не `BLOCKED`.

Использованы официальные источники: [Blocky configuration](https://0xerr0r.github.io/blocky/main/configuration/), [Blocky release v0.35.0](https://github.com/0xERR0R/blocky/releases/tag/v0.35.0), [HaGeZi list formats](https://github.com/hagezi/dns-blocklists), [Remnawave Config Profiles](https://docs.rw/learn-en/config-profiles/).
