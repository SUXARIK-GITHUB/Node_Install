# Node Install 2.5.18 / r54 — этап 1: исправления после аудита

Дата: **2026-11-12**. Статус: **INCOMPLETE_STAGING_ONLY**. Основа: r53, сохранены все каталоги и файлы из исходного ZIP.

## Изменения

1. В `install.sh` защищённый каталог состояния, лог и каталог копий могут создаваться до backup. Но `install-version`, `owned-installation`, скопированный установщик, `/etc/vkarmani-node`, `/opt/vkarmani-node`, библиотека Node и enrollment каскадной роли записываются **только после** создания копии исходного системного состояния и SHA-256-проверки её файлов. `install-version` коммитится атомарно через временный файл.
2. Добавлен `tests/test_r54_verified_backup.py` с симуляцией отказа `cp`, отказа проверки SHA-256, проверкой отсутствия маркеров на неуспехе и повторной успешной попыткой. Тест использует реальный блок команд установщика, однако заменяет входные пути копирования на временные фикстуры.
3. Четыре Nginx-тестовых модуля используют пять локальных temp-path директорий; их проверка `nginx -t` и отдельные loopback-проверки больше не зависят от системного каталога `/var/lib/nginx/body`.
4. Перенесена проверка в историческом `test_resume_ntp.py`, которая требовала небезопасный порядок записи версии. Обновлена сборочная идентичность README/CHANGELOG/manifest и регрессионные тесты; новые сборки проверяются всеми правилами r53.

## Безопасные локальные проверки

```bash
unzip -t Node_Install_2.5.18-docs-menu_20261112-r54-backup-ci-pass1-staging.zip
cd Node_Install
sha256sum --check SHA256SUMS
python3 scripts/verify_release.py --root .
bash -n install.sh
bash tests/run.sh
```

**Rollback (только при будущей установке на staging):** сначала создать и проверить внешний snapshot у хостера. Если установка/сеть/SSH прервутся, восстанавливать исходный VPS из snapshot через консоль хостера, а не вручную удалять промежуточные маркеры. Для уже работающей production-ноды не применять архив как автоматическую миграцию.
