How to use these guides

  1. Clear history

    A readable history groups related changes into logical commits. Make commit subjects describe intent instead of repeating filenames.

  2. Review notes

    Review notes should identify a specific risk, test or trade-off. A useful review makes it clear what needs fixing and why.

  3. Tagged releases

    A tagged release connects a known source state to a distributable artifact. Make sure the tag points to the code actually shipped.

  4. Reliable branches

    Branches are easier to maintain when integrations happen in small verified steps. Decide how conflicts and failed pipelines will be handled in advance.

Start here: A review checklist for a small commit

A readable commit records one coherent change and its test evidence. This exercise stays within a disposable repository.

  1. Create a tiny sample project and make one focused change, keeping generated artifacts and unrelated files outside the patch.

  2. Inspect the diff line by line for accidental credentials, changed permissions and forgotten test expectations.

What to notice: Scope: Diff only includes required files.; Safety: No credentials or machine-specific paths.; Reproducibility: Clean checkout reproduces the checks.
