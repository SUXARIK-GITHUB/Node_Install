How to use these guides

  1. Useful schemas

    A schema documents field names, types and constraints that implementations can agree on. Include a valid sample and one invalid boundary case.

  2. Version compatibility

    Compatibility is not guaranteed merely by matching version numbers. Check which optional fields and behaviors each implementation actually supports.

  3. Readable formats

    Human-readable formats ease debugging, but ambiguous conventions create integration errors. Specify encoding, dates, number formats and absent values.

  4. Reference examples

    Reference examples should demonstrate normal input and errors. Keep test fixtures small enough for a reader to understand without hidden dependencies.

Start here: A readable format compatibility note

Interoperability is easier to maintain when a data example includes its schema, version rules and failure behavior.

  1. Define three fields in an illustrative JSON record, including their types and whether they are required or optional.

  2. Write a valid example and one intentionally invalid variant; explain how a consumer should reject or interpret each field.

What to notice: Schema: Types and missing-value behavior are explicit.; Example: Valid and invalid records are distinguishable.; Version: Breaking changes have a documented path.
