Questions

Answers on tracing a request, latency distributions and related reading from Edge Metrics.

Tracing a request: Where does a request trace begin?

Follow one request across boundaries using a consistent trace identifier.

Latency distributions: What does a slow tail tell us?

A median hides slow outliers: compare p50 and p95 on the same workload, with enough requests to make the tail meaningful. Mark cache hits separately from misses.

Quiet dashboards: How should the first dashboard be organized?

Design a dashboard with one panel for demand, one for errors and one for latency. Beside each, write the operational decision that panel is meant to support.

What should I check in this material: First observation?

Take a deliberately illustrative set of response times in milliseconds: 80, 82, 85, 91, 95, 98, 102, 105, 109 and 900. The median is 96.5 ms, while the slowest request takes 900 ms. Their arithmetic mean is 174.7 ms. Each statistic answers a different question, and ten observations are not enough to predict a production percentile. What should I check in this material: Second observation?

Before comparing a new release with an old one, use the same request mix, region, load and measurement interval. Name both the client-observed duration and server processing time. If a trace spans several services, verify clock alignment and avoid adding overlapping spans as though they were sequential work. What should I check in this material: Further reading?

An alert description should state the symptom, minimum duration, affected population and a first check. For example, a sustained rise in failed requests may justify investigation; one isolated slow browser request rarely does. Every threshold is local to the system being observed. What are the limits of this exercise?

Averages conceal a surprisingly large range of request experiences. A dashboard should separate errors, ordinary latency and long-tail delays, then explain what each panel can and cannot prove. A new alert is useful only if its threshold has an owner and a clear response; a colored graph without a decision attached often produces noise.
