Вопросы

Ответы о «Чистый интерфейс», «Полезные тесты» и практические материалы издания Библиотека кода.

Чистый интерфейс: Как определить границу функции?

Граница функции яснее, когда её входы и ошибки названы прямо.

Полезные тесты: Какие ошибки проверяют полезные тесты?

Тестируйте результат на границе модуля, а не внутренний порядок вызовов. Для парсера особенно полезны пустой ввод, неверная кодировка и неожиданное поле.

Границы модулей: Как увидеть лишнюю связанность модулей?

Нарисуйте границы трёх модулей и стрелки их зависимостей. Попробуйте мысленно поменять формат ответа одного модуля, не переписывая два остальных.

Что проверить в этом материале: Пустой словарь?

Явная ошибка об отсутствующем обязательном поле, без необработанного traceback. Пример: Назовите обязательные поля и их типы. Для необязательных запишите значение по умолчанию. Например, поле timeout должно быть целым положительным числом, а отсутствие необязательного label не должно вызывать исключение.

Что проверить в этом материале: timeout = "5"?

Либо документированное преобразование, либо предсказуемый отказ; не молчаливое угадывание. Пример: Составьте таблицу тестов на границе модуля: минимальный корректный ввод, пустой словарь, строка вместо числа и неожиданное поле. Для каждого случая сформулируйте ожидаемый результат до запуска тестового кода.

Что проверить в этом материале: Неизвестный ключ?

Заранее выбранное правило: ошибка схемы или игнорирование с фиксацией совместимости. Пример: Проверьте контракт отдельно от реализации. Если тест упал после внутреннего рефакторинга при неизменном результате, вероятно, он был слишком тесно привязан к устройству функции.

Какие есть ограничения?

Это учебный пример, а не спецификация конкретной библиотеки. Тексты ошибок, типы и значения по умолчанию должны совпадать с реальным интерфейсом.
