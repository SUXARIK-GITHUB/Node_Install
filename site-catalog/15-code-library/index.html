Как пользоваться материалами

  1. Чистый интерфейс

    Хороший интерфейс сообщает, какие значения принимает функция и какие ошибки возможны. Небольшой пример вызова помогает понять контракт быстрее, чем общее описание назначения.

  2. Полезные тесты

    Тестируйте результат на границе модуля, а не внутренний порядок вызовов. Для парсера особенно полезны пустой ввод, неверная кодировка и неожиданное поле.

  3. Границы модулей

    Связанность заметна, когда одно изменение требует правок в пяти соседних местах. Попробуйте выделить публичный контракт и оставить детали реализации внутри одного модуля.

  4. Релизы без спешки

    Перед выпуском составьте минимальный путь возврата: сохранённая версия, миграции с учётом данных и проверка после отката. Отдельно отметьте операции, которые нельзя отменить автоматически.

С чего начать: Контракт функции: проверка без догадок

Рассмотрим небольшую функцию, которая принимает словарь настроек и возвращает нормализованный результат. Условия приёма данных лучше записать прежде, чем писать тесты: это позволяет читателю отличить ошибку пользователя от дефекта программы.

  1. Назовите обязательные поля и их типы. Для необязательных запишите значение по умолчанию. Например, поле timeout должно быть целым положительным числом, а отсутствие необязательного label не должно вызывать исключение.

  2. Составьте таблицу тестов на границе модуля: минимальный корректный ввод, пустой словарь, строка вместо числа и неожиданное поле. Для каждого случая сформулируйте ожидаемый результат до запуска тестового кода.

Что отмечать: Пустой словарь: Явная ошибка об отсутствующем обязательном поле, без необработанного traceback.; timeout = "5": Либо документированное преобразование, либо предсказуемый отказ; не молчаливое угадывание.; Неизвестный ключ: Заранее выбранное правило: ошибка схемы или игнорирование с фиксацией совместимости.
