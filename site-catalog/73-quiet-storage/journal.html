Backup rotation

Rotation protects against accidental deletion only when old copies remain recoverable.

Backup rotation should include the files, configuration and a documented restore process. Keep at least one copy beyond the failure domain of the primary host.

Write a rotation policy for a small sample dataset, distinguishing recent, monthly and archived copies. Explain which copy can be removed without losing a recovery path.

02 / Technology

Cold storage

A cold copy needs a documented way to bring it back online.

Cold storage may be slow to access, so retrieval time belongs in recovery planning. Confirm that the media and decryption method remain available.

Make a cold-storage inventory with formats, encryption-key custody and a dated readability check. Physical distance alone does not guarantee an accessible archive.

03 / Technology

Recovery points

Recovery points should reflect how much change can be lost safely.

Recovery points define how much recent work could be lost. Match the interval to the importance of the data and test a representative restore.

Draw a recovery timeline that includes discovery, authorization, restoration and validation. Mark the point at which normal writes can safely resume.

Hash verification

Hashes can detect changes but do not replace a restoration test.

A hash comparison detects byte changes between copies. It does not replace opening the recovered file or validating a restored database.

Create a checksum ledger for sample files and document when it is generated and checked. A matching digest does not replace a test of the restored application.

What to look for: A cold-storage inventory that can be restored

A retention policy is meaningful only when someone can explain which copy survives a lost device, a corrupted file or an accidental deletion. Record independent storage locations and recovery points without exposing credentials. A rotation chart should be tested against a disposable restore, not accepted because its scheduled job ran on time.

Field guide

A cold-storage inventory that can be restored

An offline copy is only useful if you can identify its contents and read it after a device fails. This exercise uses disposable sample files.

Method

  1. Create a small directory of test documents and record file names, sizes, checksums and the intended destination medium.
  2. Copy the directory to a disconnected device and verify the checksum list from the copy rather than trusting the transfer dialog.
  3. Restore into a separate empty folder and note the required software, access permissions and any missing filename metadata.

Limits and safety

Do not include production secrets or treat one backup medium as sufficient resilience. Verify recovery periodically.
