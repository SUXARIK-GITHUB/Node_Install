# Изменения

## 1.3.5 — 2026-09-26

Основа: приложенный `Node_Install-v1.3.4-GitHub(1).zip`.

### Исправлено

- Локальный TLS-check больше не передаёт Selfsteal-домен вместо API SNI. Служебное имя вычисляется из публичного JWT-ключа и CA по протоколу Remnawave (HKDF SHA-256, `rw-v1`). Ошибка воспроизведена с включённой SNI-проверкой сервера. В Node 3.4.x с выключенной проверкой старый SNI сам по себе не обязан вызывать отказ.
- В полной установке убрана лишняя активация oneshot `vkarmani-node.service` после запуска Compose. Этот unit имеет `ExecStop`; оставлять его active противоречило выбранной схеме автозапуска через Docker. Ремонт также оставляет его неактивным.
- При ремонте удаляются старые переопределения управляемых `SECRET_KEY`, `NODE_PORT`, `TZ` из Compose `environment`, сохраняется их единственный источник `env_file`. Проверяются переменные именно работающего контейнера.

### Добавлено

- `--repair-connection [--refresh-image]`: ограниченный ремонт RemnaNode API, сохранение ключей/профиля, резервная копия и попытка отката; без ОС, Nginx, sysctl и reboot. Обновление образа возможно отдельно от полной установки.
- `--diagnose-node`: read-only аудит локального API через временные диагностические файлы.
- `--diagnose-panel ADDRESS [PORT] [BACKEND_CONTAINER]`: read-only доступ к БД своего backend, авторизованный mTLS/JWT healthcheck из его сетевого пространства; приватные ключи остаются в памяти контейнера.
- Разделение успешной локальной проверки, успешного прямого авторизованного API-запроса и полной работоспособности VPN. Проверяются состояние карточки, назначенный профиль и число inbound без их изменения.
- Дополнительный диагностический X25519-запрос при TLS-ошибке. Не применяется как изменение конфигурации и не объявляется доказательством MTU-проблемы.
- Воспроизводимые тесты и описание границ проверки.

### Подтверждённый upstream-риск, а не доказанная причина данного инцидента

В Node 3.3.x обязательная SNI-проверка нарушала совместимость со старыми панелями. В 3.4.x она по умолчанию отключена, mTLS и JWT сохранены. Если старая нода закреплена по digest, обычный перезапуск не обновит её. Это основание для отдельного обновления образа, но не доказательство, что пользователь работал именно на 3.3.x.
