# Проверка VKarmani Node Installer 1.2.0

Дата: 25 сентября 2026. Основа — node-only установщик предыдущей поставки.
**Проверена программа и её генерируемые конфигурации, не развёртывание рабочей VPS.**

## Фактический результат

`python3 -m unittest discover -s tests -v`: **55 тестов, OK, без пропущенных тестов**.
Включены проверки:

- Три вопроса Bash-коллектора: SECRET_KEY → IPv4 панели → домен.
- Скрытый ввод в настоящем псевдотерминале, включая ключ длиннее 4096 байт.
- Приём `SECRET_KEY="..."`, нормализация домена и передача в Python через stdin.
- Отсутствие ключа в захваченном выводе и права 0600 сохранённых файлов.
- Отказ на частном/неверном IPv4, инъекциях и неправильной структуре credentials.
- Восстановление echo/canonical-настроек терминала после Ctrl+C во время ввода ключа.
- Повторный запуск без /dev/tty и без вопросов; сохранение прежнего ключа.
- Ошибка DNS не записывает config.json и remnanode.env новой установки.
- Валидация mTLS/JWT payload, согласованности сертификата/ключа/CA; проверка срока после синхронизации времени.
- Постоянство сгенерированных REALITY-ключей и XHTTP path; без Vision flow.
- Разделение готовности инфраструктуры, локального Xray и неподтверждённого VPN/панели.
- Реальная загрузка install.sh с локального HTTP-сервера через `bash <(curl -fsSL ...) --help`.
- Три варианта обрыва внутри функции: Bash не выполняет неполное тело установщика.
- Генерация команды для OWNER/REPO и отказ на инъекциях в URL.
- Эвристический сканер обнаруживает синтетический encoded SECRET_KEY/PEM, но не выводит их значение.

В тестах используются только сгенерированные тестовые ключи, временные каталоги,
локальный HTTP и mock-ответы сетевой конфигурации/DNS. Никакие тестовые команды
не развёртывают ноду и не меняют firewall или загрузку этого контейнера.

## Статические проверки и конфигурации

`python3 tests/check_artifacts.py` завершился успешно:

- Bash syntax: итоговый install.sh, сборщик ввода, health script, 5 встроенных shell-программ.
- Python AST: основной helper и 3 встроенных Python-блока.
- `--help` работает без установки и без запросов ключей.
- **7 systemd units** прошли `systemd-analyze verify` с временным root и заглушками зависимостей/исполняемых файлов.
- **Nginx HTTP и TLS-конфигурации** прошли настоящий `nginx -t` с временным самоподписанным сертификатом.
- `systemd-analyze calendar` разобрал понедельник 04:00 Europe/Moscow.
- Проверены инварианты: вопросы до apt-get, отсутствие IP-пресета/API-режима,
  отсутствие открытого для всех Node Port, host networking без published bridge ports,
  отсутствие volume/system prune и запрета SSH-ключей.

Сырые результаты находятся в `docs/test-results/`.
Среда запуска тестов выдавала предупреждение Python 3.13 о forkpty после многопоточного
HTTP-теста; тесты PTY завершились успешно. Это особенность тестового процесса,
а не результат проверки настоящего SSH-развёртывания.

## Проверка публикации

Проверены итоговые исходники, документация и тесты: рабочий SECRET_KEY из исходного
пользовательского compose и прежний IPv4 панели **не найдены**. Значения не записаны в отчёт.
Эвристический `tools/check-publication.py` не обнаружил совпадений в поставке.
В текстовых файлах нет UTF-8 BOM и CRLF. Сборка не содержит старых пользовательских
compose, каталогов состояния установленной VPS, приватных сертификатов и .git-истории.

Это ограниченная проверка известных значений и признаков, не гарантия отсутствия
любого секрета или уязвимости. SHA256SUMS обеспечивает сравнение файлов, но не является
цифровой подписью издателя. Контрольная сумма, полученная с того же скомпрометированного
источника, сама по себе не защищает от подмены.

## Что не проверялось

Установка на реальную Ubuntu/Debian VPS, full-upgrade, внешний выпуск/продление
Let's Encrypt, реальный UFW/SSH/IPv6/GRUB и перезагрузка, соединение с пользовательской
панелью и сквозной трафик клиента не выполнялись.
GitHub repository не создавался и файлы в аккаунт владельца не загружались.
GitHub Actions workflow добавлен, но в GitHub ещё не запускался.

Перед распространением команде требуется пробное развёртывание на отдельной VPS,
назначение профиля в панели, reboot, `vkarmani-node-check` и подключение реальным клиентом.
